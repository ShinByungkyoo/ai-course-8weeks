## 이번 주에 할 일

Week 6까지의 앱은 **여러분 브라우저 안에서만** 작동했어요. 이번엔 외부 세계와 통신합니다.

만들 것: **AI 챗봇 웹앱** (Gemini API 연결)

지금까지 배운 것들 위에:
- **API**: 외부 서비스와 대화하는 규격.
- **API 키**: 그 서비스를 쓸 수 있는 열쇠.
- **환경변수**: 비밀 정보를 코드와 분리하는 방법.
- **서버 요청**: 브라우저가 아닌 서버에서 API 호출 (보안).
- **스트리밍**: 답변이 한 글자씩 흘러나오는 UX.

## 5분 개념

### API가 뭐야?

**API (Application Programming Interface)** = 프로그램끼리 대화하는 규격.

카톡을 예로 들면:
- 여러분이 친구에게 메시지 보내기 → 카톡 앱이 카톡 서버로 요청 → 서버가 처리 → 친구에게 도착.
- 이때 **앱과 서버가 대화하는 규격**이 API입니다.

Gemini도 마찬가지:
- 여러분 앱이 "이 질문 답해줘" 요청 → Google의 Gemini 서버가 처리 → 답변 리턴.

### API 키

Gemini는 유료 서비스입니다. 아무나 요청하면 곤란하죠. 그래서 각 사용자에게 고유한 **API 키**를 발급해요.

여러분 앱이 Gemini에게 요청할 때 이 키를 함께 보내면:
- Google이 "아, 김지은이 요청했구나" 확인
- 요청 처리 + 김지은 계정에 요금 청구

### 환경변수

API 키를 코드에 그대로 쓰면 안 됩니다. 왜?
- 코드는 GitHub 같은 곳에 올라가는데, 키가 유출되면 다른 사람이 여러분 이름으로 마구 씀 → 요금 폭탄
- 그래서 **환경변수**라는 별도 저장소에 키를 두고, 코드는 "환경변수에서 키를 읽어와"라고만 씀

Vercel에는 이 환경변수를 관리하는 UI가 있고, v0는 이걸 자동으로 세팅해줍니다.

### 클라이언트 vs 서버

웹앱은 두 곳에서 실행돼요:

- **클라이언트(브라우저)**: 사용자의 크롬 창.
- **서버**: Vercel의 컴퓨터.

API 키를 클라이언트에 두면 → 브라우저 개발자 도구로 누구나 볼 수 있음 → 유출 위험.

**정답**: API 키는 서버에만. 브라우저 → 우리 서버(Vercel) → Gemini 서버 → 우리 서버 → 브라우저. 이렇게 서버가 중간에서 처리.

Next.js는 이 구조를 아주 쉽게 만들어줘요. **API Route**라는 개념으로.

<a href="https://v0.dev" target="_blank">v0.dev</a> → **+ New Project**.

```

Next.js App Router로:

전체 화면 구조:
- 상단 헤더: 로고 (이니셜 or 이모지) + 앱 제목 "AI 챗봇" + 우측에 "대화 초기화" 버튼

- 하단 입력 영역: 메시지 입력창 (multiline, Shift+Enter 줄바꿈, Enter 전송) + 전송 버튼

대화 UI:
- 사용자 메시지: 오른쪽 정렬, 파란 말풍선, 흰 글씨
- AI 메시지: 왼쪽 정렬, 회색 말풍선, 검은 글씨
- 각 메시지 아래 발신 시각 (예: "오후 3:14")
- AI가 응답 중: 왼쪽에 "..." 로딩 애니메이션 
  (점 3개가 순차적으로 튀는 형태)

기술 요구사항:
1. Gemini SDK 사용 (@google/generative-ai 또는 최신 공식 SDK)
2. API 호출은 반드시 서버에서만 (app/api/chat/route.ts로)
   - 환경변수 GEMINI_API_KEY 사용
   - 클라이언트에서는 절대 API 키를 볼 수 없어야 함
3. 응답은 스트리밍으로 (Server-Sent Events 또는 ReadableStream)
   - 사용자 경험: 답변이 한 글자씩 흘러나오는 것처럼
4. 모델: gemini-2.5-flash

대화 상태 관리:
- messages 배열에 사용자 & AI 메시지 저장 
  ({ role: "user" | "assistant", content: string, time: string })
- 매 API 요청 시 전체 대화 히스토리를 함께 전달 (문맥 유지)
- localStorage에 messages 저장 (새로고침해도 이전 대화 유지)

시스템 프롬프트 (챗봇의 성격):
"너는 대학생을 돕는 친절한 학습 도우미야. 
답변은 명확하고 간결하되, 초보 눈높이의 비유를 활용해. 
답변 마지막에 '혹시 더 궁금한 게 있어?'를 붙여."

에러 처리:
- API 요청 실패 시 대화 영역에 빨간 에러 메시지 + "재시도" 버튼
- 429 (rate limit) → "지금 요청이 많아요. 잠시 후 다시 시도해주세요"
- 401/403 → "API 키가 유효하지 않아요. 관리자에게 문의해주세요"

UX 디테일:
- 새 메시지가 오면 대화 영역이 자동으로 아래로 스크롤
- 사용자 메시지 전송 후 입력창 즉시 비우고 focus 유지
- AI 응답 중에는 입력창이 disabled (동시 요청 방지)
- "대화 초기화" 버튼: 확인 팝업 → localStorage와 상태 모두 클리어

디자인:
- 카톡 or 챗GPT 스타일
- 화이트 배경, 부드러운 그레이 라인
- 다크모드 지원 (우측 상단 토글)

모바일:
- 전체 화면 채우기
- 입력창은 하단 고정 (키보드 올라와도 가리지 않게)
- 상단 헤더는 얇게

가장 중요한 것:
- **API 키는 절대 클라이언트로 보내지 않기**. 
  모든 Gemini 호출은 app/api/chat/route.ts 안에서만.
```

## Step 6. 코드 뒷면 살펴보기 (선택)

미리보기 옆 **"Code"** 탭 → 다음 파일들 확인:

### 클라이언트 (사용자 브라우저에서 실행)

```typescript
// app/page.tsx (요약)
"use client";
export default function ChatPage() {
  const [messages, setMessages] = useState([]);
  
  const sendMessage = async (text: string) => {
    // ⭐ 우리 서버의 API Route로 요청 (Gemini에게 직접이 아님)
    const response = await fetch("/api/chat", {
      method: "POST",
      body: JSON.stringify({ messages: [...messages, { role: "user", content: text }] })
    });
    // 응답 스트리밍 받아서 UI 업데이트
    ...
  }
}
```

### 서버 (Vercel에서 실행)

```typescript
// app/api/chat/route.ts
export async function POST(req: Request) {
  const { messages } = await req.json();
  
  // ⭐ 환경변수에서 API 키 읽음 (클라이언트는 이걸 볼 수 없음)
  const apiKey = process.env.GEMINI_API_KEY;
  
  // Gemini에게 요청
  const geminiResponse = await callGemini(apiKey, messages);
  
  // 결과를 클라이언트로 스트리밍
  return new Response(geminiResponse.stream, {
    headers: { "Content-Type": "text/event-stream" }
  });
}
```

이 두 파일의 역할이 명확히 나뉘어 있죠? 이게 이번 주 개념의 핵심입니다.

## Step 8. Publish (배포)

**Publish** 버튼 → 배포.

**⚠️ 매우 중요**: 배포 후에도 **환경변수(API 키)가 프로덕션 환경에 있어야** 실제 URL에서 챗봇이 작동해요.

배포 후 확인:
1. 배포된 URL 접속.
2. 시크릿 브라우저에서 열어보기 (로그인 상태 없이).
3. 챗봇에게 대화 시도.
4. **AI가 답변하는가?**

답변이 안 나오면:
- **Vercel Dashboard**로 이동 (vercel.com/dashboard).
- 프로젝트 선택 → **Settings** → **Environment Variables**.
- `GEMINI_API_KEY`가 **Production 환경**에 등록되어 있는지 확인.
- 없으면 추가 후 **Deployments** 탭에서 **최신 배포를 Redeploy**.

## 자주 발생하는 상황

### ❌ "API key not found" 또는 401 에러

**해결**: 
1. 로컬 미리보기 → v0의 Env Vars에 `GEMINI_API_KEY` 등록 확인.
2. 배포 URL → Vercel Dashboard의 Env Vars 확인.
3. Redeploy 필요할 수 있음.

### ❌ 답변이 스트리밍 안 되고 한 번에 뚝 옴

**원인**: 서버 응답이 스트리밍 방식이 아님.

**해결**:
```
API Route에서 응답을 스트리밍으로 바꿔줘.
Content-Type: text/event-stream, 
ReadableStream 사용해서 chunk를 즉시 클라이언트로 전달.

클라이언트에서는 fetch 응답의 body.getReader()로 
청크를 하나씩 받아 UI 업데이트.
```

### ❌ 이전 대화를 기억 못함

**원인**: 매 요청마다 히스토리를 안 보냄.

**해결**:
```
API 호출 시 현재 상태의 messages 배열 전체를 요청에 포함.
서버는 이 배열을 Gemini의 contents로 전달.
```

### ❌ CORS 에러 콘솔에 뜸

**원인**: 클라이언트에서 Gemini에 직접 요청하고 있음.

**해결**:
```
Gemini API 호출은 반드시 서버(app/api/chat/route.ts)에서만.
클라이언트는 우리 서버의 /api/chat 엔드포인트만 호출.
```

### ❌ Rate Limit (429)에 자주 걸림

**해결**:
- 유료 요금제 확인.
- 여러 사용자가 같이 쓸 거라면 API 키를 각자 발급.

## 심화 - 이미지 첨부 기능 (선택)

Gemini는 이미지도 이해합니다. 챗봇에 이미지 첨부 기능을 붙여봅시다.

```
채팅 입력창 옆에 이미지 첨부 버튼(클립 아이콘) 추가.
- 클릭 시 파일 선택 대화상자 (jpg, png, webp 허용, 최대 5MB)

서버 처리:
- 이미지는 base64로 인코딩해서 Gemini의 contents에 추가
- Part type: image with inline data

사용 예시:
- 옷장 사진 + "오늘 뭐 입지?" → 코디 추천
- 냉장고 사진 + "저녁 뭐 만들지?" → 레시피
- 문제집 사진 + "이 문제 도와줘" → 풀이
```
