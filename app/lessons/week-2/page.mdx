## 이번 주에 할 일

지난주엔 즉흥으로 페이지 하나 만들어봤죠. 이번 주부터는 **진짜 개발자·기획자가 프로덕트를 시작하는 방식**을 배웁니다.

첫 단계는 **기획(Discovery)**. 코드 한 줄 짜기 전에 다음 4가지를 정합니다.

1. **문제** — 어떤 불편함을 해결하려는가?
2. **사용자** — 누가 이걸 쓰나?
3. **해결책** — 이걸로 어떻게 도와주나?
4. **MVP** — 최소한 무엇이 있어야 쓸모 있나?

이걸 한 장에 정리한 게 **PRD (Product Requirements Document)**. 이번 주 결과물이 이 PRD 한 장입니다.

## Part 1. 왜 PRD를 먼저 쓰나?

이유는 하나예요. **개발 도중 방향이 흔들리지 않기 위해서.**

PRD 없이 만들기 시작하면:
- "이 기능도 있어야 하지 않나?" → 무한 추가
- "이건 왜 이렇게 만들었지?" → 이유 잃어버림
- "이 앱을 도대체 누가 쓰지?" → 뒤늦게 깨달음

PRD가 있으면:
- 새 기능 아이디어가 뜰 때: "이게 PRD 목표에 도움 되나?" → No면 나중으로.
- 시간이 부족할 때: "MVP만 지키면 된다" → 결정 빠름.
- 남들에게 설명할 때: "우리 앱은 이걸 하는 앱이야" → 30초 안에 전달.

**한 장짜리** PRD가 좋습니다. 길면 아무도 안 봐요.

## Part 3. PRD 작성 - 5단계

### Step 1. 문제 정의 (Problem Statement)

**공식**: `[누구]가 [상황]에서 [무엇] 때문에 불편하다.`

**예시**:
- 대학생이 논문 읽을 때 핵심 파악에 오래 걸린다.
- 자취생이 저녁 메뉴 고를 때 냉장고 재료 활용을 못 한다.
- 취업 준비생이 자소서 첨삭받을 곳이 마땅치 않다.

한 문장으로 명확하게. 애매하면 만들 것도 애매해집니다.

### Step 2. 페르소나 (Target User)

**공식**: 실제 한 명을 상상하듯 자세히.

**예시**:
```
이름: 김소연
나이: 22세
직업: 국문학과 3학년
상황: 매주 논문 2편씩 리딩 과제. 시간 부족.
현재 대응: 형광펜 + 챗GPT 붙여넣기
가장 큰 불만: PDF 표·수식은 챗GPT가 잘 못 알아봄
```

**추상적인 "20대 대학생"보다 "김소연 22살"이 명확합니다.** 결정할 때 "김소연이 이걸 좋아할까?"로 판단하기 좋아요.

### Step 3. 유저 스토리 3~5개

**공식**: `[페르소나]로서, 나는 [기능]하고 싶다, 그래서 [이유].`

**예시** (논문 요약 앱):
```
1. 학생으로서, 나는 PDF를 업로드하면 5분 안에 3줄 요약을 받고 싶다,
   그래서 오늘 읽을 논문인지 빠르게 판단할 수 있다.

2. 학생으로서, 나는 논문의 특정 개념을 클릭하면 상세 설명을 볼 수 있으면 좋겠다,
   그래서 낯선 용어에서 막히지 않는다.

3. 학생으로서, 나는 여러 논문을 함께 비교할 수 있으면 좋겠다,
   그래서 리터러처 리뷰 과제를 쉽게 할 수 있다.

4. 학생으로서, 나는 요약을 노션에 그대로 붙여넣을 수 있으면 좋겠다,
   그래서 노트 정리가 편하다.
```

### Step 4. MVP 정의

**MVP (Minimum Viable Product)** = 이 정도만 있어도 실제로 사용 가능한 최소 기능 세트.

**공식**: 유저 스토리를 **Must have / Nice to have / Later**로 분류.

**예시**:
```
Must have (Week 8까지):
- PDF 업로드
- 3줄 요약 표시
- 3~5개 핵심 용어 자동 추출 + 설명

Nice to have (여유 있으면):
- 여러 논문 비교 (2개까지)
- 노션 export 버튼

Later (이 강의 이후):
- 협업 (팀원과 하이라이트 공유)
- 논문 자동 추천
```

**MVP는 반드시 8주 안에 끝낼 수 있는 최소한**으로 정하세요. 학생들이 자주 하는 실수는 MVP를 너무 크게 잡는 것.

### Step 5. 성공 지표 (Success Metric)

이 앱이 성공했는지 어떻게 측정할까요?

**예시**:
- 실사용자 3명이 실제 논문 5편에 이 앱을 씀
- 그 중 2명 이상이 "다음에도 쓰겠다"고 응답
- 논문 하나 요약받는 데 30초 이내 걸림

숫자로 표현할 수 있는 게 좋아요.

## Part 5. Hands-On 프로젝트 훑는 팁

리포 페이지에서 훑을 때 이렇게 접근:

1. **README의 카테고리별 소개**를 먼저 읽어 전체 감 잡기.
2. **관심 가는 프로젝트 5개** 후보로 표시.
3. 그 5개의 개별 README (예: `ai_agents/personal_finance_agent/README.md`) 클릭해 자세히 읽기.
4. **여러분에게 진짜 필요한 문제**를 다루는 것 하나만 픽.
5. 그 프로젝트를 그대로 만들지 말고, **여러분 페르소나에 맞게 재정의**.

**예시**: `receipt_expense_tracker`를 참고했다면:
- 원본: 영수증 사진 → 지출 정리 (파이썬 데스크톱)
- 여러분 버전: 영수증 사진 → 지출 정리 **+ 카테고리별 월간 통계 시각화** (웹앱, 대학생 자취용)

## 이번 주 과제

1. **PRD 1페이지 완성 & 제출** (필수). Notion 공유 링크 or Google Docs 링크.
2. Hands-On-AI-Engineering에서 **최소 3개 프로젝트를 훑어**본 뒤 그 중 하나를 참고 소스로 명시.
3. **친구 or 스터디원 1명에게 PRD 보여주고 피드백** 받기. 페르소나·MVP가 명확한지 검증.
4. **선택 도전**: 페르소나 인터뷰 1~2회. 실제로 그 사람과 대화해서 "정말 이게 문제인지" 검증.
