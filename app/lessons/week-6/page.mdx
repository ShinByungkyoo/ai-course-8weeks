## 이번 주에 할 일

Week 5까지 만든 앱은 저장은 잘 되지만 **아직 똑똑하지 않아요**. 사용자가 자소서를 저장해도 그냥 저장만 되고 끝. 여기에 **AI가 진짜로 첨삭해주는 기능**을 붙입니다.

### 이번 주가 끝나면

- 저장된 자소서 → **AI가 자동으로 3가지 관점 첨삭**
- 답변이 **한 글자씩 흘러나오는** 자연스러운 표시
- 첨삭 결과도 자동으로 저장되어 **다음에 열면 즉시 표시**

## 개념 - 세 가지 새 용어를 일상 언어로

이번 주 낯선 단어 3개가 나옵니다. 미리 쉽게 설명합니다.

### 1. API — "다른 서비스에 부탁하기"

여러분 앱이 Gemini에게 "**이 자소서 첨삭해줘**"라고 부탁하려면, Gemini와 대화하는 통로가 필요해요. 이 통로가 **API**.

일상 비유:
- 여러분 앱 = **손님**
- Gemini = **셰프**
- API = **주문서 양식** ("이런 형식으로 부탁하세요" 라는 규격)

### 2. API 키 — "부탁할 때 내는 회원증"

Gemini는 유료 서비스. 아무나 마구 부탁하면 곤란하니, 각 사용자에게 **회원증 번호**를 발급합니다. 이걸 **API 키**라고 불러요.

부탁할 때 이 키를 함께 보내면 → Gemini가 "**아, 김지은이 부탁했구나**" 알아채고 → 처리 후 → 김지은 계정에 요금 청구.

### 3. 환경변수 — "회원증을 지갑에 넣어두기"

**회원증을 앱 코드에 그대로 쓰면 절대 안 됩니다.** GitHub에 올리거나 페이지 소스코드로 노출되면 → 다른 사람이 여러분 이름으로 마구 씀 → 요금 폭탄.

그래서 **회원증은 별도의 안전한 자리**(지갑)에 넣어두고, 코드는 "**지갑에서 회원증 꺼내와**"라고만 씁니다. 이 지갑을 **환경변수**라고 불러요.

Vercel, Cloud Run 같은 배포 플랫폼마다 지갑 UI가 있어서, 여러분은 거기에 키를 넣기만 하면 됩니다.

## 어떤 앱에 AI 기능이 필요할까? (실제 상황별 시나리오)

여러분 앱의 어디에 AI를 넣어야 할지 감이 안 잡히면 아래 예시를 참고하세요.

### 시나리오 A: 자소서 첨삭 앱

사용자가 자소서를 저장한 뒤:
- **"AI가 3가지 관점(구조·임팩트·회사 적합성)으로 첨삭"** 결과를 자동으로 보여줌.
- 사용자가 "다시 첨삭받기" 누르면 다른 관점으로 재첨삭.

### 시나리오 B: 논문 요약 앱

사용자가 PDF를 업로드한 뒤:
- **"3줄 요약"** 자동 생성.
- 사용자가 특정 개념을 클릭하면 **"이 개념 쉽게 설명해줘"**.

### 시나리오 C: 여행 계획 앱

사용자가 목적지·기간을 입력하면:
- **"3박 4일 추천 일정"** 자동 생성.
- 사용자가 특정 날 클릭하면 **"이 날 대체 옵션 3개"**.

### 시나리오 D: 냉장고 셰프

사용자가 냉장고 사진을 올리면:
- **"이 재료로 만들 수 있는 요리 3가지 + 레시피"** 생성.

### 시나리오 E: 학습 로그

사용자가 오늘 배운 걸 붙여넣으면:
- **"자동으로 카테고리·태그 붙이기"**.
- 주말에 **"이번 주 학습 요약 & 다음 주 계획 제안"**.

모두 공통 패턴: **사용자가 뭔가 입력 → AI가 처리 → 결과 표시**.

## 단계 2. AI Studio Build에 첨삭 기능 요청

여러분 프로젝트 대화창에 아래 프롬프트를 복사·붙여넣기.

```
/result 페이지에서 자소서를 AI가 자동으로 첨삭하도록 만들어줘.

동작 순서:
1. 사용자가 /result?id=xxx로 들어옴.
2. 브라우저 저장소에서 그 id의 자소서를 불러옴.
3. 이미 첨삭 결과가 저장되어 있다면 그대로 표시 (재생성 안 함).
4. 첨삭 결과가 없다면 자동으로 AI 첨삭 시작:
   - 로딩 중: "AI가 자소서를 읽고 있어요..." 스피너
   - AI 응답이 한 글자씩 화면에 흘러나옴 (스트리밍)
5. 첨삭 완료 후 결과를 브라우저 저장소에 저장 
   (다음 방문 시 재생성 안 함).

AI 첨삭 3가지 관점:
1. 구조 - 핵심 메시지가 명확한가? 문단 흐름이 자연스러운가?
2. 임팩트 - 지원 회사·직무에 대한 관심이 구체적으로 드러나는가?
3. 회사 적합성 - 지원자와 회사의 매칭 근거가 있는가?

각 관점에 대한 출력 형식 (마크다운):

## 1. 구조
### 잘된 점
- [구체적 인용과 함께 2~3개]
### 개선할 점
- [구체적 지적 2~3개]
### 개선 예시
[한 문단 다시 써주기]

(2, 3도 동일 형식)

AI 호출 설정:
- 모델: gemini-2.5-flash (빠르고 저렴)
- 시스템 지시: "당신은 15년차 인사담당자입니다. 
  자소서를 3가지 관점으로 첨삭합니다. 원문 인용은 인용부호로. 
  회사·직무 정보를 반드시 첨삭에 반영."
- 스트리밍: true

보안 요구사항 (매우 중요):
- API 키는 절대 클라이언트(브라우저)에서 노출되면 안 됨.
- Next.js의 API Route (app/api/critique/route.ts)에서만 API 키 사용.
- 환경변수 GEMINI_API_KEY를 서버 코드에서 process.env로 읽음.
- 클라이언트는 /api/critique로만 요청 (직접 Gemini와 통신 X).

UI 세부사항:
- 첨삭이 스트리밍되는 동안 자동으로 아래로 스크롤.
- 각 섹션에 아이콘 (📋 구조, 💥 임팩트, 🎯 적합성).
- 마크다운을 실제 heading·bold·bullet로 렌더링 (react-markdown 사용).
- 페이지 하단에 "다시 첨삭받기" 버튼 
  (누르면 기존 결과 무시하고 재요청).

에러 처리:
- API 호출 실패 시: 빨간 박스로 "AI가 지금 바빠요. 잠시 후 다시 시도해주세요" 
  + 재시도 버튼.
- 401/403 오류: "API 키에 문제가 있어요. 관리자에게 문의해주세요."
- 429 오류: "요청이 너무 많아요. 1분 뒤 다시 시도해주세요."
```

**Run** → 3~5분 대기.

## 단계 3. 회원증을 지갑에 넣기 (환경변수 등록)

AI Studio Build가 코드를 만들었지만, **아직 회원증(API 키)이 어디에도 없어요**. 등록해야 실제로 작동합니다.

### 3-1. AI Studio Build 안에서 등록

AI Studio Build 상단 어딘가 **"⋮ 메뉴"** 또는 **"Settings"** → **"Environment Variables"** 또는 **"Secrets"**.

- **Key** (이름): `GEMINI_API_KEY`
- **Value** (값): 단계 1에서 발급받은 실제 키 (`AIzaSy...`)

**Save**.

### 3-2. 미리보기 새로고침

미리보기 창의 새로고침 아이콘 or **⟳** 눌러 다시 실행.

## 단계 4. 실제로 첨삭받아보기

미리보기에서 진짜로 동작하는지 확인.

1. `/edit`에서 새 자소서 작성 & 저장.
2. 자동으로 `/result?id=xxx`로 이동.
3. **"AI가 자소서를 읽고 있어요..." 로딩이 뜬 뒤**
4. **답변이 한 글자씩 흘러나오는가?**
5. 3개 섹션이 모두 채워지는가?
6. 완료 후 F5 새로고침해도 결과가 그대로 뜨는가?

이 6가지가 다 되면 성공.

## 단계 5. 배포된 URL에서도 작동하게

미리보기에선 잘 되는데 **배포된 URL에서 안 되는 경우가 흔합니다**. 회원증을 배포 환경에도 등록해야 하기 때문.

### 5-1. Vercel의 경우

<a href="https://vercel.com/dashboard" target="_blank">vercel.com/dashboard</a>:

- 여러분 프로젝트 클릭 → **Settings** → **Environment Variables**.
- **Add New**:
  - Key: `GEMINI_API_KEY`
  - Value: 여러분 실제 키
  - Environment: **Production**, **Preview**, **Development** 3개 다 체크.
- **Save**.
- **Deployments** 탭 → 최신 배포 우측 **⋯** → **Redeploy**.

### 5-2. Cloud Run의 경우

AI Studio Build가 Cloud Run으로 배포한 경우:

- <a href="https://console.cloud.google.com/run" target="_blank">console.cloud.google.com/run</a>.
- 서비스 선택 → **Variables & Secrets** 탭.
- **Add Variable**: `GEMINI_API_KEY` + 여러분 키.
- **Deploy** 클릭 → 새 개정판 배포.

### 5-3. 확인

배포된 URL로 접속 → 새 자소서 저장 → 실제로 첨삭이 되는지.

## 단계 7. 실전 상황별 팁

### AI 답변이 너무 짧아요

시스템 지시에 길이 규칙 추가:

```
[내 프로젝트]의 AI 답변이 너무 짧아. 
시스템 지시를 이렇게 강화해줘:

"답변은 반드시 다음 3가지를 포함:
1. 판단 (한 문장)
2. 근거 (3~5문장)
3. 실행 가능한 제안 (2~3개)

전체 500자 이상, 1200자 이하."
```

### 답변에서 페르소나(성격)가 흐트러져요

대화가 길어지면 AI가 초반 지시를 잊습니다.

```
매 API 요청마다 시스템 지시가 확실히 포함되도록 해줘. 
대화가 길어져도 첨삭 어투와 형식이 흔들리지 않게.
```

### 스트리밍이 안 되고 한 번에 뚝 나옴

```
답변이 스트리밍으로 흘러나오지 않고 
완성 후 한 번에 뜨는 문제가 있어. 

Gemini API를 스트리밍 방식(generateContentStream)으로 호출하고, 
API Route도 스트리밍 응답을 전달하도록 (ReadableStream 사용). 
클라이언트는 청크를 하나씩 받아 화면에 이어붙임.
```

### 마크다운 서식이 원본 텍스트로 뜸

`# 제목` 같은 게 그대로 화면에 보이는 경우.

```
AI 답변의 마크다운을 실제 heading·bold·bullet로 
렌더링하도록 react-markdown 라이브러리를 사용해줘.
```

### 요금이 걱정돼요

Gemini 2.5 Flash는 저렴해서 강의 전체 기간 몇천 원 이내. 하지만 실수로 무한 루프 요청을 보내면 폭탄 가능.

**대비책**:
1. 단계 1-4에서 설정한 **예산 알림**을 반드시 확인.
2. 앱에 **재시도 제한** 걸기:

```
같은 자소서에 대해 AI 첨삭 재요청은 
사용자가 명시적으로 "다시 첨삭받기" 버튼을 누를 때만.
자동 재시도는 최대 3회, 그 뒤엔 사용자 확인 팝업.
```

## 단계 8. 다른 AI 기능 하나 더 추가하기 (선택)

시간이 있으면 앱을 더 풍성하게. 예를 들어 자소서 앱에 **"자소서 초안 자동 생성"** 기능.

```
/edit 페이지 상단에 "AI가 초안 만들어주기" 버튼 추가.

동작:
1. 사용자가 회사명·직무만 입력하고 이 버튼 클릭.
2. AI가 그 회사·직무에 맞는 자소서 초안 (700~1000자) 생성.
3. 결과가 자소서 textarea에 자동 입력됨 (사용자가 수정 가능).

시스템 지시:
"당신은 취업 준비생의 자소서 초안 작성 파트너입니다.
회사·직무 정보를 받아 다음 4단계 구조로 초안을 작성:
1. 지원 동기 (2~3문장)
2. 관련 경험·역량 (3~4문장)
3. 회사·직무에 대한 이해 (2~3문장)
4. 입사 후 포부 (2~3문장)

톤: 진솔하고 구체적. 과장 금지. 예시가 있는 표현 선호."

주의: 이 기능은 초안 작성용이지 완성본이 아님을 사용자에게 명시:
- 버튼 클릭 시 확인 팝업:
  "AI가 만든 초안이에요. 반드시 여러분 이야기로 수정한 뒤 제출해주세요."
```

## 이번 주 과제
