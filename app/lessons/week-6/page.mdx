### 결과물

## Part 1. 개념 - API·API 키·환경변수

### API

**API (Application Programming Interface)** = 프로그램끼리 대화하는 규격.

- 여러분 앱 → Gemini 서버로 "이 텍스트 요약해줘" 요청
- Gemini 서버 → 여러분 앱으로 결과 응답

이 대화가 API 호출입니다.

### API 키

Gemini는 유료 서비스. 아무나 요청하면 곤란하니 각 사용자에게 **API 키**를 발급합니다. 요청할 때 이 키를 함께 보내면 → "김지은 계정에 요금 청구" 됩니다.

### 환경변수 (Environment Variable)

API 키를 코드에 그대로 쓰면 안 됨. GitHub·CodePen에 올라가면 유출 → 다른 사람이 여러분 이름으로 마구 씀 → 요금 폭탄.

그래서 **환경변수**라는 별도 저장소에 키를 두고, 코드는 "환경변수에서 키를 읽어와"라고만 씁니다.

- Vercel: 프로젝트 Settings → Environment Variables
- Google Cloud Run: 서비스의 Variables 탭
- 로컬 개발: `.env.local` 파일 (이 파일은 절대 커밋 안 함)

### 클라이언트 vs 서버

웹앱은 두 곳에서 돌아요.

- **클라이언트(브라우저)**: 사용자의 크롬. 소스코드 다 노출됨.
- **서버(백엔드)**: Vercel의 컴퓨터. 소스코드 숨겨져 있음.

**API 키는 절대 클라이언트에 두면 안 됩니다.** 브라우저 개발자 도구로 누구나 볼 수 있어요.

Next.js App Router는 **API Route** (또는 **Server Action**) 기능으로 이 구조를 쉽게 만들어줍니다. AI Studio Build도 이걸 자동으로 처리해요.

## Part 2. Gemini API 키 발급

<a href="https://aistudio.google.com/app/apikey" target="_blank">**aistudio.google.com/app/apikey**</a>

1. **"+ Create API key"** 클릭.
2. 프로젝트 선택 → 기본 그대로.
3. `AIzaSy...` 로 시작하는 긴 문자열이 나옴 → 복사.
4. **메모장에 임시로 저장** (절대 SNS·GitHub·공개 코드에 올리지 마세요).

**Paid tier 확인**: API keys 페이지에서 여러분 프로젝트 옆에 "Paid tier" 표시가 있어야 원활히 작동. 없으면 **"Set up billing"** 진행.

**일일 예산 알림 설정 (권장)**: <a href="https://console.cloud.google.com/billing" target="_blank">Google Cloud Console → Billing</a> → Budgets & alerts → Create budget → 5,000원 정도 알림 걸어두기.

## Part 3. Hands-On 리포에서 참고 패턴 찾기

Week 2에서 참고했던 <a href="https://github.com/Sumanth077/Hands-On-AI-Engineering" target="_blank">**Hands-On-AI-Engineering**</a>을 다시 열어보세요.

여러분 프로젝트의 AI 기능과 유사한 패턴을 사용하는 프로젝트를 하나 찾아 코드를 읽어봅니다. **파이썬이라 그대로 못 쓰지만, "어떤 흐름"을 알 수 있어요.**

### 자주 쓰는 5가지 AI 패턴

| 패턴 | 뭐하는 건가 | 참고 프로젝트 |
|---|---|---|
| **요약** | 긴 텍스트 → 짧게 | `rag_apps/reasoning_rag` |
| **분류** | 텍스트 → 카테고리 | `ai_agents/customer_query_routing_agent` |
| **추출** | 텍스트/이미지 → 구조화 데이터 | `OCR/receipt_expense_tracker` |
| **생성** | 프롬프트 → 새 텍스트 | `ai_agents/job_posting_agent` |
| **QA (RAG)** | 문서 + 질문 → 답 | `rag_apps/youtube_transcript_rag` |

여러분 앱은 이 중 어떤 패턴에 해당하나요?

### 예시 매핑

- **자소서 첨삭 앱** → **분석·생성** 패턴 (원문 분석 + 개선안 생성)
- **논문 요약 앱** → **요약·QA** 패턴
- **여행 계획 앱** → **생성** 패턴 (요청 → 일정 생성)
- **가계부 앱** → **추출** 패턴 (영수증 → 데이터)

패턴을 확인했으면 참고 프로젝트의 README·핵심 코드를 5분만 훑어보세요. 시스템 프롬프트가 어떻게 짜여있는지, 어떤 정보를 API에 넘기는지 감이 옵니다.

## Part 4. AI Studio Build에 AI 기능 요청

이제 여러분 앱에 실제로 AI를 붙입시다. 자소서 첨삭 앱 예시.

같은 대화창(Week 4·5에서 쓰던)에 요청:

```
/result 페이지에서 AI가 실제 자소서 첨삭을 하도록 만들어줘.

기술 요구사항:
1. Next.js App Router의 서버 액션 or Route Handler 사용.
2. Gemini API 호출은 반드시 서버에서만 (app/api/critique/route.ts).
3. 환경변수 GEMINI_API_KEY 사용. 클라이언트에서 노출되면 안 됨.
4. 모델: gemini-2.5-flash (빠르고 저렴).
5. 스트리밍 응답 사용 (한 글자씩 흘러나오게).

AI 기능 흐름:
1. /result 페이지 마운트 시, URL의 id로 localStorage에서 자소서 불러오기.
2. 이미 첨삭된 경우 (localStorage에 결과 있음) 그대로 표시.
3. 첨삭 안 된 경우:
   - 자동으로 /api/critique 호출
   - 스트리밍으로 3개 섹션 순차 출력
4. 완료되면 결과를 localStorage에 저장 (다음 방문 시 재사용).

시스템 프롬프트 (서버 코드에 상수로):
"당신은 15년차 인사담당자입니다. 사용자가 제출한 자소서를 
다음 3가지 관점으로 첨삭합니다:

1. 구조: 핵심 메시지가 명확한가? 문단 흐름이 자연스러운가?
2. 임팩트: 지원 회사·직무에 대한 관심이 구체적으로 드러나는가?
3. 회사 적합성: 지원자와 회사가 잘 맞는지 근거가 있는가?

각 관점에 대해 다음 형식의 마크다운으로 답합니다:

## 1. 구조
### 잘된 점
- [구체적 인용과 함께 2~3개]
### 개선할 점
- [구체적 지적 2~3개]
### 개선 예시
[한 문단 다시 써주기]

... (2, 3도 동일 형식)

규칙:
- 반드시 마크다운.
- 원문 인용은 인용부호로.
- 회사·직무 정보를 항상 첨삭에 반영.
- 확실하지 않으면 명시."

응답 처리:
- 마크다운을 실제 렌더링 (heading·bullet·bold 반영).
- 로딩 중: "지금 첨삭하는 중이에요..." 표시.
- 오류 시: 재시도 버튼 + 오류 메시지.
- 완료 후 /history에서 해당 자소서 상태 배지가 "첨삭 완료"로 바뀜.

UX 디테일:
- 첨삭이 스트리밍되는 동안 스크롤 자동으로 하단 유지.
- 각 섹션마다 아이콘 (📋 구조, 💥 임팩트, 🎯 적합성).
- "다시 첨삭받기" 버튼 (누르면 캐시 무시하고 재요청).
```

## Part 5. 배포 환경변수 세팅

배포된 URL에서도 AI가 작동하려면 **프로덕션 환경에도 API 키가** 있어야 합니다.

### AI Studio Build의 Publish

AI Studio Build로 배포한 경우:
- Publish 화면에 **"Environment Variables"** 섹션.
- Key: `GEMINI_API_KEY`, Value: 여러분 실제 키.
- Save → Redeploy.

### Vercel로 배포한 경우

- Vercel Dashboard → 프로젝트 → **Settings → Environment Variables**.
- Add: `GEMINI_API_KEY`.
- **Production, Preview, Development** 모두 체크.
- Save → Deployments 탭에서 최신 배포 **Redeploy**.

### 확인

배포된 URL에서 실제로 첨삭을 돌려보세요.
- 스트리밍이 되는가?
- 결과가 localStorage에 저장되는가?
- 재방문 시 캐시된 결과가 나오는가?

## Part 6. 흔한 문제와 해결

### ❌ 401 / API key not valid

**해결**:
1. `.env.local` (로컬) 또는 프로덕션 환경변수 재확인.
2. 키에 앞뒤 공백 없는지.
3. API 키 발급 페이지에서 그 키의 restriction (HTTP referrer 등) 확인.

### ❌ 429 Too Many Requests

**해결**: Paid tier 확인. 여러 명이 함께 쓰는 강의라면 학생마다 개인 키 발급 권장.

### ❌ 스트리밍 안 되고 한 번에 뚝

**해결**:
```
API Route 응답을 정말 스트리밍으로 바꿔줘. 
ReadableStream 사용해서 chunk를 즉시 반환. 
클라이언트에서는 response.body.getReader()로 청크 하나씩 처리.
```

### ❌ 마크다운이 원본 텍스트로 보임

**해결**: 마크다운 렌더러 필요. `react-markdown` 라이브러리 사용 요청.

```
AI 응답의 마크다운을 실제 heading·bullet·bold로 렌더링하도록 
react-markdown 라이브러리를 사용해서 렌더링 컴포넌트를 만들어줘.
```

### ❌ localStorage 캐시가 계속 오래된 결과를 씀

**해결**: 
```
[다시 첨삭받기] 버튼을 눌렀을 때는 localStorage의 result 캐시를 무시하고 
새로 API를 호출하도록 수정.
```

## Part 7. 프로젝트별 AI 기능 아이디어

각 프로젝트 타입에 맞는 AI 활용 예시.

### 자소서 첨삭 앱
- ✅ 3가지 관점 첨삭 (구조·임팩트·적합성)
- 개선안 문장 자동 생성
- 회사 최신 뉴스 반영 (Grounding)

### 논문 요약 앱
- 3줄 요약, 챕터 요약
- 핵심 용어 자동 추출 + 설명
- 시각화 (개념 관계 그래프)

### 여행 계획 앱
- 일정 자동 생성
- 예산 추정
- 추천 명소 (Grounding으로 실시간)

### 가계부 앱
- 영수증 이미지 → 자동 파싱 (Vision)
- 월간 지출 분석·인사이트
- 절약 제안

### 뉴스 큐레이터
- 관심사 기반 추천
- 매일 하이라이트 요약
- 중복·유사 기사 병합

### 학습 로그
- 학습 내용 자동 태그·카테고리
- 주간 회고 자동 생성
- 다음 학습 계획 제안
