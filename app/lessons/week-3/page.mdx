## 이번 주에 할 일

Week 2에서 **PRD**로 뭘 만들지 정했어요. 이번 주는 그걸 **눈에 보이는 화면**으로 옮깁니다. 설계(Design) 단계.

산출물 3가지:
1. **사이트맵**: 앱에 어떤 페이지가 몇 개 필요한지
2. **유저 플로우**: 사용자가 그 페이지들을 어떤 순서로 이동하는지
3. **와이어프레임**: 각 페이지에 뭐가 어디 배치되는지 (저충실도)
4. **디자인 토큰**: 색깔·폰트·간격 규칙

이 4가지가 Week 4 개발의 재료가 됩니다.

## Part 1. 사이트맵 - 앱의 지도

**사이트맵** = 앱의 페이지 구조를 나무 모양으로 그린 것.

**예시** (논문 요약 앱):

```
📱 앱 홈 (/)
├── 새 논문 업로드 (/upload)
├── 내 논문 목록 (/library)
│   ├── 개별 논문 상세 (/library/[논문id])
│   └── 논문 비교 (/library/compare)
└── 설정 (/settings)
```

### 왜 필요한가?

- **몇 페이지를 만들어야 할지 명확**해집니다.
- 페이지 간 관계가 보여요 (어느 페이지에서 어느 페이지로 이동 가능).
- Week 4에서 AI Studio Build에 프롬프트 넣을 때 정확한 요구사항이 됩니다.

### 그리는 요령

- **3~7페이지가 적정**. 8주짜리 프로젝트에는 5페이지가 최대치.
- 페이지마다 URL 경로도 함께 표시 (예: `/upload`, `/library`).
- 큰 그룹이 있으면 폴더처럼 계층으로.

### 여러분 프로젝트 사이트맵 그리기

Week 2의 PRD를 열고, Must have 기능들을 페이지로 매핑하세요.

**예시** — 자소서 첨삭 앱:
```
자소서 첨삭 도우미
├── 홈 (/) — 앱 소개 + "시작하기" 버튼
├── 자소서 입력 (/edit) — 텍스트·회사·직무 입력
├── 첨삭 결과 (/result/[id]) — 3가지 관점 첨삭 표시
└── 지난 자소서 (/history) — 저장된 것들 목록
```

## Part 2. 유저 플로우 - 사용 시나리오

**유저 플로우** = 첫 방문부터 목표 달성까지 사용자가 화면을 어떻게 오가는지.

**예시** (논문 요약 앱, 첫 방문 시나리오):

```
[홈] 
  ↓ "PDF 업로드" 버튼
[업로드 화면]
  ↓ PDF 드래그
  ↓ AI 분석 로딩
[논문 상세 화면]
  ↓ 요약 확인 + 용어 클릭
[용어 팝업]
  ↓ 닫기
[논문 상세로 복귀]
  ↓ "노션에 저장" 버튼
[성공 토스트: "저장됨"]
```

### 3가지 시나리오만 만들면 충분

- **첫 방문 시나리오**: 앱을 처음 열었을 때
- **핵심 사용 시나리오**: 앱의 주 목적 달성
- **재방문 시나리오**: 이미 데이터 있는 사용자가 다시 왔을 때

### 그리는 도구

- **종이에 화살표로**: 가장 빠름
- **Figma FigJam** (무료): 협업 가능
- **Miro** (무료 티어): 온라인 화이트보드
- **draw.io** (무료): 다이어그램 전용

## Part 3. 와이어프레임 - 화면 스케치

**와이어프레임** = 각 페이지에 무엇이 어디에 있을지 그린 저충실도 스케치.

**"예쁘게 그리기"가 목적이 아니라 "무엇이 필요한지 파악"이 목적**. 대충 네모와 글자로 표시하는 게 정석입니다.

### 저충실도 vs 고충실도

| 저충실도 (Lo-Fi) | 고충실도 (Hi-Fi) |
|---|---|
| 흑백, 대충 네모와 글자 | 실제 색깔·이미지·폰트 |
| 종이 + 연필 or Figma 사각형 | Figma로 실제 UI에 가깝게 |
| 5~15분에 화면 하나 | 화면당 1~2시간 |
| **아이디어 검증용** | 개발 넘길 때 |

**이 강의는 저충실도로만.** 우리에겐 AI Studio Build가 있어서 고충실도 목업은 필요 없어요. AI가 알아서 예쁘게 만들어줍니다.

### 와이어프레임 배치 규칙

한 화면은 대체로 이런 구조:

```
┌────────────────────────────────┐
│ 헤더 (로고 · 메뉴)                │
├────────────────────────────────┤
│                                │
│         메인 콘텐츠              │
│                                │
├────────────────────────────────┤
│ 푸터 (저작권 · 링크)              │
└────────────────────────────────┘
```

메인 콘텐츠에 뭐가 들어가는지가 페이지마다 다릅니다.

### 5가지 표준 레이아웃

앱은 대개 이 5가지의 조합으로 만들어져요:

1. **랜딩(Landing)**: 상단 히어로 + 아래 여러 섹션.
2. **폼(Form)**: 입력창들 + 제출 버튼.
3. **리스트(List)**: 카드 여러 개가 그리드로.
4. **상세(Detail)**: 큰 이미지·제목·본문·관련 정보.
5. **대시보드(Dashboard)**: 통계·차트·표.

Week 2의 PRD를 보고 각 페이지가 어느 레이아웃에 해당하는지 정하세요.

### 와이어프레임 그리기 실습

**예시** — 자소서 첨삭 앱의 `/edit` 화면:

```
┌──────────────────────────────────────┐
│  🎓 자소서 첨삭   [홈] [지난 자소서]      │
├──────────────────────────────────────┤
│                                      │
│  회사명: [___________________]         │
│  직무:  [___________________]          │
│                                      │
│  자소서 본문:                          │
│  ┌────────────────────────────────┐  │
│  │                                │  │
│  │  (여기에 텍스트 입력...)          │  │
│  │                                │  │
│  │                                │  │
│  └────────────────────────────────┘  │
│                                      │
│           [ ✨ 첨삭받기 ]              │
│                                      │
├──────────────────────────────────────┤
│  © 2026 · Contact                    │
└──────────────────────────────────────┘
```

이런 식으로 여러분 앱의 3~5개 화면을 그리세요.

## Part 4. 디자인 토큰 - 컬러·타이포 시스템

**디자인 토큰** = 색깔·폰트·간격의 재사용 가능한 규칙.

이걸 미리 정해두면 AI Studio Build에 프롬프트 넣을 때 **일관된 결과**가 나옵니다.

### 컬러 팔레트 (5색)

- **Primary**: 앱의 대표 색깔 (버튼·강조).
- **Secondary**: 보조 색깔 (링크·아이콘).
- **Background**: 배경.
- **Text**: 본문 글자.
- **Border/Muted**: 경계선·비활성 요소.

**팁**: <a href="https://coolors.co/palettes/trending" target="_blank">**coolors.co**</a>에서 마음에 드는 팔레트 골라 5색 HEX 코드 복사.

**예시** (자소서 앱, 프로페셔널 톤):
```
Primary:    #2563EB (진한 블루)
Secondary:  #7C3AED (바이올렛)
Background: #F8FAFC (오프 화이트)
Text:       #0F172A (다크 네이비)
Muted:      #64748B (그레이)
```

### 폰트 2개

- **본문용**: 산세리프 (가독성). 예: Pretendard, Noto Sans KR.
- **강조용**: 세리프 or 굵은 산세리프 (제목). 예: Nanum Myeongjo, Gowun Batang.

한글 폰트는 <a href="https://fonts.google.com/?subset=korean" target="_blank">Google Fonts 한국어</a>에서 찾으세요.

### 간격 규칙 (Spacing)

- 4px 단위로 통일 (4, 8, 12, 16, 24, 32, 48, 64, 96).
- 여백은 넉넉히 (초보의 흔한 실수: 여백이 너무 좁음).

## Part 5. 디자인 문서 템플릿

Week 2의 PRD 아래에 이어서 추가하거나, 별도 문서로.

```md
# [프로젝트] 디자인 문서

## 사이트맵
[Notion·Google Docs에 트리 형태로 넣기]

## 유저 플로우
### 시나리오 1: 첫 방문
[화살표 다이어그램 or 텍스트]

### 시나리오 2: 핵심 사용
...

### 시나리오 3: 재방문
...

## 와이어프레임
[각 페이지 스케치 이미지 삽입]
- 홈 (/)
- 폼 (/edit)
- 결과 (/result)
...

## 디자인 토큰

### 컬러
- Primary: #____
- Secondary: #____
- Background: #____
- Text: #____
- Muted: #____

### 폰트
- 본문: [폰트 이름]
- 강조: [폰트 이름]

### 간격 규칙
- 기본 padding: 24px
- 카드 간격: 16px
- 섹션 간격: 64px

## 무드 참고
[참고하고 싶은 앱 스크린샷 3~5개 링크 or 이미지]
- 예: 토스 홈 (미니멀·여백 많음)
- 예: 애플 프로덕트 페이지 (큰 타이포그래피)
```

## Part 6. 무드 참고 자료

와이어프레임과 디자인 토큰이 어색하면, **좋은 사이트를 참고**하세요.

### 한국 서비스 참고

- **토스**: 미니멀·여백·둥근 코너
- **당근**: 컬러풀·친근함·큰 텍스트
- **네이버 웨일**: 시원한 청량감
- **카카오 브런치**: 세리프·문학 감성

### 해외 참고

- **Linear**: 다크 미니멀 (dev 도구)
- **Notion**: 클래식 세리프 (문서 도구)
- **Vercel**: 흑백+포인트 (개발자 감성)
- **Stripe**: 컬러풀·정교함

원하는 무드를 정하고, 그 사이트 스크린샷을 참고 자료로 저장.

## 이번 주 과제

1. **사이트맵 + 유저 플로우 + 와이어프레임 (3~5개 화면) + 디자인 토큰** 문서 완성.
2. Week 2의 PRD와 함께 하나의 Notion 페이지 or Google Docs로 정리.
3. **친구·스터디원 1명에게 보여주고** "이 앱이 뭐하는 앱인지" 즉시 이해되는지 검증.
4. **선택 도전**: Figma FigJam에서 화면 스케치를 마우스로 그려보기. 무료.
