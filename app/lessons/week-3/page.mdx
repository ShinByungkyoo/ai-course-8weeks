## 이번 주에 할 일

지난주엔 세로로 긴 **한 페이지**를 만들었죠. 이번 주엔 **여러 페이지가 있는 진짜 웹사이트**를 만듭니다.

만들 것: **개인 포트폴리오 사이트**

- `/` — 홈 (첫 화면)
- `/about` — 나에 대해
- `/projects` — 프로젝트 모음
- `/contact` — 연락처

**각 페이지가 다른 URL**을 가지고, 네비게이션 메뉴로 이동합니다.

## 5분 개념 - 라우팅

**라우팅(Routing)** = URL과 페이지를 연결하는 규칙.

예를 들어 여러분 웹사이트가 `myportfolio.vercel.app`이라면:

| URL | 어떤 페이지가 뜰까요? |
|---|---|
| `myportfolio.vercel.app/` | 홈 페이지 |
| `myportfolio.vercel.app/about` | 소개 페이지 |
| `myportfolio.vercel.app/projects` | 프로젝트 페이지 |
| `myportfolio.vercel.app/contact` | 연락처 페이지 |

`/뒤에 붙는 부분(경로)`이 페이지를 결정합니다. 이걸 **라우트(route)**라고 불러요.

### Next.js와 App Router

v0는 **Next.js**라는 프레임워크로 웹사이트를 만들어요. Next.js의 **App Router**는 이렇게 동작합니다:

```
app/
├── page.tsx              → /
├── about/
│   └── page.tsx          → /about
├── projects/
│   └── page.tsx          → /projects
└── contact/
    └── page.tsx          → /contact
```

**폴더 이름 = URL 경로**입니다. 아주 직관적이죠.

여러분이 이 파일 구조를 직접 만들 필요는 없어요. v0에게 "이런 페이지들이 필요해" 하면 알아서 만들어줍니다. 다만 **왜 그렇게 만들어지는지** 알면 나중에 앱을 이해할 때 편해요.

## Step 1. 프로젝트 시작

<a href="https://v0.dev" target="_blank">v0.dev</a> → **+ New Project**.

## Step 2. 4개 페이지 요청

아래 프롬프트를 복사 → 여러분 정보로 수정 → 붙여넣기.

```
문과대학 국문학과 3학년 김지은의 개인 포트폴리오 웹사이트를 만들어줘.

Next.js App Router 구조로, 다음 4개의 페이지가 있어야 해:

1. / (홈)
   - 히어로 섹션: "안녕하세요, 김지은입니다" + 부제
   - "About Me →" 큰 버튼 (클릭하면 /about으로 이동)
   - 최근 프로젝트 3개 하이라이트 카드 (클릭하면 /projects로 이동)

2. /about
   - 페이지 제목: "About Me"
   - 왼쪽 프로필 이미지, 오른쪽 자기소개 텍스트
   - 스킬·관심사 태그들
   - 학교/전공/학년 정보

3. /projects
   - 페이지 제목: "Projects"
   - 프로젝트 카드 그리드 (6개, 반응형 3열 → 2열 → 1열)
   - 각 카드: 이미지 자리, 제목, 짧은 설명, 태그, "View →" 링크

4. /contact
   - 페이지 제목: "Get in Touch"
   - 이메일, 인스타그램, 브런치 카드 3개 (각각 이메일 열기, 인스타 열기 등 링크)
   - "간단한 문의" 폼 (이름/이메일/메시지) — 지금은 눌러도 아무것도 안 해도 OK
     (다음 주에 실제 이메일 전송 기능을 추가할 예정)

공통 요소 (모든 페이지에 표시):
- 상단 헤더: 왼쪽 로고 (이니셜 "JE" 원형), 오른쪽 메뉴 (홈/About/Projects/Contact)
  - 현재 있는 페이지의 메뉴 항목이 강조되도록 (색상 or 밑줄)
- 하단 푸터: 이메일, SNS 링크, 저작권

디자인:
- 미니멀, 모던 (토스 or 노션 느낌)
- 색상: 화이트 배경, 짙은 남색(#0F172A) 텍스트, 파란색(#3B82F6) 강조
- 폰트: Pretendard (한글에 최적)
- 각 페이지 넉넉한 여백
- 부드러운 페이지 전환 (fade)

라우팅:
- 헤더의 메뉴 클릭 시 next/link의 <Link>로 부드럽게 이동 (페이지 새로고침 없음)
- 활성 메뉴 항목 표시 (usePathname 사용)

모바일:
- 상단 메뉴는 햄버거 아이콘으로 접기
- 프로젝트 카드는 1열로 스택
```

**보내기** → 2~3분 대기.

## Step 3. 라우팅 테스트

미리보기에서 다음을 시도:

1. **메뉴 클릭**: 헤더의 "About" 클릭 → URL이 `/about`으로 바뀌면서 새 페이지 표시.
2. **뒤로가기**: 브라우저 뒤로가기 버튼 → 이전 페이지로.
3. **URL 직접 입력**: 미리보기 URL에 `/projects`를 붙여 접속 → 프로젝트 페이지 표시.

이게 다 되면 **라우팅이 정상 작동**하는 겁니다.

### 문제가 있을 때

**"메뉴 클릭 시 페이지가 새로고침돼요"**
```
헤더의 메뉴가 지금 <a href> 태그로 만들어져서 
클릭할 때마다 새로고침돼. 
next/link의 <Link>로 바꿔서 
페이지 전환 없이 부드럽게 이동하도록 해줘.
```

**"활성 페이지 표시가 안 돼요"**
```
현재 페이지에 해당하는 메뉴 항목이 
파란색 굵은 글씨로 표시되도록 해줘. 
usePathname() 훅을 사용해서.
```

## Step 9. 404 페이지

사용자가 존재하지 않는 URL(예: `/xyz`)에 접속하면 무슨 일이 벌어질까요? 

```

- 큰 "404" 숫자
- "이런, 존재하지 않는 페이지예요" 메시지

- 배경은 다른 페이지와 통일된 느낌
```

## Step 11. 코드가 어떻게 생겼는지 살펴보기 (선택)

미리보기 옆의 **"Code"** 탭을 눌러보세요. v0가 어떻게 페이지들을 만들었는지 볼 수 있어요:

```
app/
├── page.tsx          ← 홈 (/)
├── layout.tsx        ← 모든 페이지에 공통 (헤더/푸터)
├── about/
│   └── page.tsx      ← /about
├── projects/
│   └── page.tsx      ← /projects
├── contact/
│   └── page.tsx      ← /contact
├── not-found.tsx     ← 404
└── globals.css
```

**폴더 이름 = URL 경로**의 규칙이 여기 그대로 적용돼 있죠.

이걸 이해할 필요는 없지만 눈으로 스캔하면 감이 생겨요.

## 자주 발생하는 상황

### ❓ 메뉴 클릭 시 페이지가 깜빡거리며 새로고침됨

**원인**: v0가 `<a>` 태그로 만들어서 실제 페이지 이동이 일어남.

**해결**: `<Link>` 컴포넌트로 바꿔달라고 요청 (Step 3 참고).

### ❓ 반응형이 잘 안 됨 (모바일에서 이상)

**해결**:
```
모바일(768px 이하)에서 다음을 확인해서 수정해줘:
- 헤더 메뉴는 햄버거로 접혀야 함
- 프로젝트 카드는 1열로 스택
- 텍스트 크기가 너무 크지 않게
- 모든 섹션의 좌우 여백이 충분히
```

### ❓ 페이지 사이를 이동할 때 스크롤 위치가 이상함

**해결**:
```
페이지 이동 시 자동으로 스크롤이 맨 위로 올라가도록 해줘.
```

### ❓ 404 페이지가 안 뜸

**해결**: `not-found.tsx` 파일이 있는지 확인 요청. v0에게: `Next.js App Router의 not-found.tsx 파일로 404 페이지를 만들어줘.`

## 이번 주 과제

1. **4개 페이지짜리 포트폴리오** 완성 & Publish. URL 제출.
2. 4개 페이지가 모두 실제로 접속 가능한지 확인.
3. **활성 메뉴 하이라이트** 정상 작동.
4. **모바일 반응형** 완료.
5. **여러분 실제 정보**로 About·Projects 채우기.
6. **선택 도전**: 프로젝트 카드를 클릭하면 상세 페이지(예: `/projects/spring-poems`)로 이동하는 기능. 힌트: `v0에게: "동적 라우팅으로 각 프로젝트의 상세 페이지를 만들어줘. URL 형식은 /projects/[slug]로. 6개 프로젝트 각각의 상세 페이지를 하드코딩해도 됨."`
