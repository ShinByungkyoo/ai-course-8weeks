## 이번 주에 만들 것

**PDF 파일을 업로드하면 그 내용을 바탕으로 질문에 답해주는 앱**입니다.

- 논문 → "이 논문의 결론이 뭐야?"
- 계약서 → "위약금 조항 알려줘"
- 시험 대비 자료 → "3장 핵심 5개만 요약해"

지금까지 만든 챗봇과 뭐가 다를까요? 이전 챗봇은 **AI가 이미 알고 있는 지식**으로만 답했어요. 이번 앱은 **여러분이 준 문서**를 근거로 답합니다. 이걸 **RAG**라고 불러요.

## RAG가 뭔가요? (5분 개념)

**RAG = Retrieval-Augmented Generation (검색 증강 생성)**

이름은 무섭지만 개념은 시험 볼 때 커닝페이퍼 만드는 것과 똑같습니다.

### 커닝페이퍼 vs RAG 비유

시험장에 커닝페이퍼를 몰래 가져갔다고 상상해봅시다. 문제가 나오면:

1. 문제와 관련된 부분을 커닝페이퍼에서 찾아 (**Retrieval**, 검색)
2. 그 부분을 참고해서 답을 쓴다 (**Generation**, 생성)

RAG도 똑같습니다:

1. 사용자 질문과 관련된 PDF의 일부를 찾고 (**Retrieval**)
2. AI에게 "이 내용을 참고해서 답해줘"라며 함께 전달 (**Augmented Generation**)

### 왜 그냥 PDF 전체를 AI에게 안 주죠?

주면 좋겠지만 두 가지 문제가 있어요:

1. **비용**: PDF 100페이지를 통째로 매번 보내면 요금이 폭발합니다.
2. **정확도**: 관련 없는 내용까지 다 보면 AI가 헷갈립니다.

그래서 **관련 있는 조각만** 골라 보내는 게 핵심입니다.

### RAG 파이프라인 4단계

```
[PDF 업로드]
  ↓
[1] 조각내기 (Chunking) — 긴 문서를 500자 정도 조각으로 나눔
  ↓
[2] 숫자로 변환 (Embedding) — 각 조각을 "의미의 지문"인 숫자 벡터로 변환
  ↓
[3] 검색 (Retrieval) — 질문 벡터와 비슷한 조각들 찾기
  ↓
[4] 답변 생성 (Generation) — 찾은 조각들을 AI에게 근거로 제공
```

이 4단계를 한 주에 걸쳐 하나씩 만들어봅시다.

## Step 3. 텍스트 조각내기 (Chunking)

긴 PDF를 통으로 다루면 정확도가 떨어져요. 일정 크기로 잘라야 합니다.

**청킹 함수**를 만들어봅시다. `chunker.py` 파일:

```python filename="chunker.py"
def chunk_text(text: str, chunk_size: int = 500, overlap: int = 100) -> list[str]:
    """
    긴 텍스트를 chunk_size 글자씩 조각으로 나눔.
    앞뒤 조각이 overlap 만큼 겹치게 만들어 문맥 손실 방지.
    """
    chunks = []
    start = 0
    while start < len(text):
        end = start + chunk_size
        chunk = text[start:end]
        chunks.append(chunk)
        start = end - overlap  # 다음 조각은 overlap 만큼 앞에서 시작
    return chunks
```

### 왜 overlap이 필요한가요?

문장 중간에서 잘리면 문맥이 끊기잖아요. 예:

```
[조각 1] ...세종대왕은 훈민정음을 만들었다. 그의 업적은
[조각 2] 지대하다. 특히 과학기술 분야에서...
```

이러면 "그의 업적은 지대하다"라는 문장이 두 조각에 걸쳐 잘려버려요. **overlap**은 조각끼리 약간 겹치게 해서 이런 손실을 방지합니다.

## Step 4. Embedding — "의미의 지문"

**Embedding(임베딩)**은 텍스트를 숫자 벡터로 바꾸는 과정입니다. 왜 그러냐고요?

**컴퓨터는 "비슷한 의미"를 직접 이해 못 합니다.** 하지만 숫자로 바꿔놓으면 **가까운 숫자 = 비슷한 의미**로 다룰 수 있어요.

예를 들어 Gemini의 embedding 모델은 문장을 **768개의 숫자**로 변환합니다:

```
"세종대왕이 한글을 만들었다"  → [0.12, -0.45, 0.78, ..., 0.03]  (768개 숫자)
"조선의 4대 왕은 훈민정음을 창제했다" → [0.11, -0.44, 0.79, ..., 0.02]  (거의 비슷!)
"오늘 저녁은 김치찌개다"        → [-0.88, 0.23, -0.15, ..., 0.91]  (완전히 다름)
```

첫 두 문장은 의미가 비슷하니 숫자도 비슷하고, 셋째는 완전히 다르니 숫자도 다릅니다.

## Step 5. 유사도 검색

두 벡터가 얼마나 비슷한지 재는 **코사인 유사도(cosine similarity)**를 씁니다. 수학은 몰라도 돼요. 함수 하나만 알면 됩니다.

`similarity.py`:

```python filename="similarity.py"
import numpy as np

def cosine_similarity(a: list[float], b: list[float]) -> float:
    """두 벡터의 유사도를 -1(반대) ~ 1(똑같음) 사이 숫자로 리턴."""
    a_np, b_np = np.array(a), np.array(b)
    return float(np.dot(a_np, b_np) / (np.linalg.norm(a_np) * np.linalg.norm(b_np)))
```

## Step 6. PDF QA 앱 완성하기 🎉

이제 조각들을 모아서 진짜 PDF QA 앱을 만듭시다. **`pdf_chat.py`**:

```python filename="pdf_chat.py"
import os
import numpy as np
import streamlit as st
from dotenv import load_dotenv
from google import genai
from google.genai import types
from pypdf import PdfReader

load_dotenv()
client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

st.title("📄 PDF와 대화하기")

# --- 유틸 함수들 ---

def chunk_text(text: str, size: int = 500, overlap: int = 100) -> list[str]:
    chunks = []
    start = 0
    while start < len(text):
        chunks.append(text[start:start + size])
        start += size - overlap
    return chunks

def embed(texts: list[str]) -> list[list[float]]:
    """여러 텍스트를 한 번에 embedding으로 변환."""
    result = client.models.embed_content(
        model="gemini-embedding-001",
        contents=texts,
    )
    return [e.values for e in result.embeddings]

def cosine(a, b) -> float:
    a, b = np.array(a), np.array(b)
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

def top_k_chunks(query_vec, chunks, chunk_vecs, k=3):
    """질문 벡터와 가장 가까운 청크 k개를 리턴."""
    scores = [cosine(query_vec, v) for v in chunk_vecs]
    top_indices = np.argsort(scores)[-k:][::-1]  # 점수 높은 순
    return [(chunks[i], scores[i]) for i in top_indices]

# --- UI ---

# PDF 업로드
uploaded = st.file_uploader("PDF를 업로드하세요", type=["pdf"])

if uploaded:
    # 이미 처리한 파일이면 다시 안 함 (캐시)
    if st.session_state.get("filename") != uploaded.name:
        with st.spinner("PDF 읽는 중..."):
            reader = PdfReader(uploaded)
            full_text = "\n".join(page.extract_text() or "" for page in reader.pages)
        with st.spinner(f"{len(full_text):,}자 텍스트를 조각내는 중..."):
            chunks = chunk_text(full_text)
        with st.spinner(f"{len(chunks)}개 조각을 embedding으로 변환 중..."):
            chunk_vecs = embed(chunks)

        st.session_state.chunks = chunks
        st.session_state.chunk_vecs = chunk_vecs
        st.session_state.filename = uploaded.name
        st.session_state.messages = []

    st.success(f"✅ **{uploaded.name}** 준비 완료 ({len(st.session_state.chunks)}개 조각)")

    # 채팅 UI
    for msg in st.session_state.get("messages", []):
        with st.chat_message(msg["role"]):
            st.write(msg["content"])

    user_q = st.chat_input("PDF에 대해 무엇이든 물어보세요...")
    if user_q:
        st.session_state.messages.append({"role": "user", "content": user_q})
        with st.chat_message("user"):
            st.write(user_q)

        with st.chat_message("assistant"):
            with st.spinner("관련 부분 찾는 중..."):
                # 1) 질문을 벡터로
                q_vec = embed([user_q])[0]
                # 2) 가장 관련 있는 청크 3개 찾기
                top = top_k_chunks(q_vec, st.session_state.chunks, st.session_state.chunk_vecs, k=3)
                context = "\n\n---\n\n".join(chunk for chunk, _ in top)

            # 3) 프롬프트에 context 넣어서 AI에게 질문
            system = """
당신은 사용자가 업로드한 문서를 근거로 답변하는 도우미입니다.

규칙:
1. 답변은 반드시 아래 [참고 자료] 안의 내용만 근거로 한다.
2. 참고 자료에 없는 내용은 "문서에서 찾을 수 없습니다"라고 답한다.
3. 추측하거나 상상해서 답하지 않는다.
4. 답변 마지막에 어떤 부분을 참고했는지 짧게 언급한다.
"""
            prompt = f"[참고 자료]\n{context}\n\n[질문]\n{user_q}"

            stream = client.models.generate_content_stream(
                model="gemini-2.5-flash",
                contents=prompt,
                config=types.GenerateContentConfig(system_instruction=system),
            )
            answer = st.write_stream(chunk.text for chunk in stream)

            # 어떤 청크를 참고했는지 접힌 영역에 표시
            with st.expander(f"📎 참고한 문서 조각 {len(top)}개 보기"):
                for i, (chunk, score) in enumerate(top, 1):
                    st.markdown(f"**조각 {i}** (유사도: {score:.3f})")
                    st.text(chunk)
                    st.divider()

        st.session_state.messages.append({"role": "assistant", "content": answer})
else:
    st.info("👆 왼쪽에서 PDF 파일을 업로드하면 대화를 시작할 수 있어요.")
```

## Step 8. 성능을 조금 더 개선하기 (선택)

### 개선 1: 청크 크기 조정

- 청크가 너무 짧으면 문맥이 부족.
- 너무 길면 관련 없는 내용도 섞임.
- **일반적으로 300~800자**가 적당. 여러분 문서 타입에 맞게 실험.

### 개선 2: 검색 청크 수(k) 조정

`top_k_chunks(..., k=3)`의 k를 3~7 사이로 실험. 많으면 정확도 ↑, 비용 ↑.

### 개선 3: 페이지 번호 함께 저장

지금은 어느 페이지에서 온 조각인지 몰라요. 청킹할 때 페이지 번호를 함께 저장하면 "3페이지 참고" 같은 인용이 가능합니다.

```python
# 청킹을 페이지 단위로 하는 예시
chunks_with_pages = []
for page_num, page in enumerate(reader.pages, 1):
    text = page.extract_text() or ""
    for c in chunk_text(text):
        chunks_with_pages.append({"page": page_num, "text": c})
```

## 자주 발생하는 오류

### ❌ `PdfReadError: EOF marker not found`

**원인**: PDF 파일이 손상되었거나 스캔된 이미지 PDF.

**해결**: 다른 PDF로 시도. 스캔 PDF는 Week 5의 OCR 기술이 필요해요.

### ❌ `Resource has been exhausted` (embedding API 오류)

**원인**: 무료 요금제 embedding 한도 초과 (분당 요청 수).

**해결**: 
1. 유료 요금제 활성화 확인.
2. 청크 수를 줄이거나(청크 크기 늘리기), 짧은 PDF로 테스트.

### ❌ AI가 문서 내용을 무시하고 자기 지식으로 답변함

**원인**: 시스템 프롬프트가 약하거나 검색된 청크가 관련 없음.

**해결**:
1. 시스템 프롬프트에서 "반드시", "절대"를 강조.
2. 청크 크기·overlap을 실험해서 검색 정확도 개선.
