## 이번 주에 할 일

지금까지 만든 사이트는 **일방적**이었어요. 여러분이 보여주고, 방문자는 보기만.

이번 주엔 **양방향**으로 만듭니다. 사용자가 폼에 이름·이메일·메시지를 입력하고 **"보내기"**를 누르면 → **여러분 이메일에 도착**. 실제로 답장할 수 있는 진짜 문의 폼.

### 이번 주 결과물

- 지난주 포트폴리오의 `/contact` 페이지에 있던 폼이 **진짜로 작동**함.
- 낯선 사람이 제출한 메시지가 여러분 이메일에 도착.
- 스팸 방지 처리까지.

## 5분 개념 - 폼(Form)이란?

폼(Form) = 사용자가 정보를 입력하고 제출할 수 있는 UI 요소들의 모음.

여러분이 웹에서 매일 마주치는 폼들:
- 로그인 화면 (이메일 + 비밀번호)
- 회원가입 (이름, 이메일, 비밀번호 등등)
- 인스타 댓글 (텍스트)
- 배달앱 주문 (주소, 결제 정보)

### 폼의 3가지 요소

```
1) Input (입력창)     ← 사용자가 정보 입력
2) Validation (검증)  ← 이메일 형식 맞는지, 필수 항목 채웠는지
3) Submit (제출)      ← 어딘가로 데이터 전송
```

### 폼 제출은 어디로 갈까?

전통적으로는:
- 폼 제출 → 서버로 데이터 전송 → 데이터베이스에 저장 → 관리자 대시보드에서 열람

이거 다 구현하려면 백엔드 개발자가 필요해요. 우리는 문과생이에요.

### 대신 씁시다: Formspree

**Formspree**는 "폼을 만든 뒤 특정 URL로 제출하기만 하면, 알아서 여러분 이메일로 전송해주는 서비스"입니다. 무료 요금제로도 월 50건 폼 제출까지 처리 가능해요. 강의용으론 넘치죠.

## Step 1. Formspree 가입

<a href="https://formspree.io" target="_blank">**formspree.io**</a> 접속.

우측 상단 **"Sign up"** → **"Continue with Google"** (또는 이메일로 가입).

로그인 후 대시보드가 뜨면 **"+ New Form"** 클릭.

### 폼 정보 입력

- **Form name**: `Portfolio Contact` (아무거나 OK).
- **Send emails to**: **여러분 이메일 주소** (문의가 여기로 옵니다).
- **Create Form** 클릭.

## Step 2. Endpoint URL 복사

생성된 폼의 상세 페이지로 이동하면 상단에 **Endpoint**가 표시됩니다:

```
https://formspree.io/f/xrgjkabc
```

`xrgjkabc` 같은 짧은 문자열이 폼의 고유 ID예요. **이 URL 전체를 복사해서 메모장에 저장**하세요. Step 3에서 씁니다.

## Step 3. v0에서 지난주 프로젝트 이어서 편집

<a href="https://v0.dev" target="_blank">v0.dev</a> 대시보드 → 지난주 만든 포트폴리오 프로젝트 클릭 → 편집 재개.

**같은 대화창에서** 새 요청을 추가하세요:

```
/contact 페이지의 문의 폼을 실제로 작동하게 만들어줘.

폼 필드:
- 이름 (필수, 최소 2자)
- 이메일 (필수, 이메일 형식 검증)
- 메시지 (필수, 최소 10자, textarea로)

제출 처리:
- 아래 Formspree endpoint로 POST 요청 (fetch로):
  https://formspree.io/f/xrgjkabc
- Content-Type: application/json
- Accept: application/json

버튼 & 상태:
- 제출 버튼 텍스트: "메시지 보내기"
- 클릭 시 버튼이 disabled 되고 텍스트가 "전송 중..."으로 바뀜
- 성공 시: 폼이 사라지고 성공 메시지 표시 
  ("메시지가 잘 도착했어요! 곧 답장 드릴게요.")
- 실패 시: 에러 메시지 ("전송에 실패했어요. 잠시 후 다시 시도해주세요.")

검증 UX:
- 필수 항목이 비어있으면 제출 시 해당 필드 아래에 빨간 텍스트로 안내
- 이메일 형식이 틀리면 "이메일 형식이 올바르지 않아요"
- 유효한 입력은 필드 테두리가 초록으로

디자인:
- 폼 필드는 넓고 여유롭게 (padding 넉넉히)
- 필드 사이 간격도 넉넉
- 포커스 시 파란 링 (focus ring) 표시
- 제출 버튼은 큰 파란색으로

주의: xrgjkabc 부분은 예시야. 위에 있는 정확한 URL로 정확히 사용해줘.
```

**중요**: 위 프롬프트의 `xrgjkabc` 부분을 **여러분의 실제 endpoint**로 바꿔서 붙여넣으세요.

`Enter` → 1~3분 대기.

## Step 4. 첫 테스트 전송

미리보기에서 실제로 폼을 채워봅시다.

- 이름: 여러분 이름
- 이메일: **여러분 다른 이메일 주소** (테스트용, 본 계정과 다른 것이 좋음)
- 메시지: "테스트 메시지입니다"

**"메시지 보내기"** 클릭.

### 3가지 확인

1. **버튼이 "전송 중..."으로 바뀌는지**
2. **성공 메시지가 뜨는지**
3. **여러분 이메일함**에 Formspree로부터 온 메일이 있는지

### 첫 제출은 인증 필요

Formspree는 **첫 제출 후 여러분 이메일로 인증 링크**를 보냅니다. 그 링크를 클릭해 인증해야 이후 제출을 계속 받을 수 있어요. 이건 스팸 방지용.

인증 후 다시 폼을 제출하면, 이제 진짜로 실시간 이메일이 옵니다. 🎉

## Step 5. 검증 UX 다듬기

폼이 사용자에게 친절해야 해요. 다음 시나리오들을 테스트하고 v0에게 개선 요청.

### 시나리오 1: 아무 것도 안 채우고 제출

- ❌ 아무 반응 없이 그냥 넘어감 (나쁨)
- ✅ 각 필수 필드 아래에 "이 항목은 필수예요" 표시 (좋음)

v0에게:
```
빈 채로 제출하면 필수 항목 아래에 "필수 항목이에요"라고 
빨간 글씨로 뜨게 해줘.
```

### 시나리오 2: 이메일에 "가나다" 같은 이상한 값

- ❌ 그냥 서버로 보내버림
- ✅ "올바른 이메일 형식이 아니에요" 안내

v0에게:
```
이메일 필드에 실시간 검증을 추가해줘.
- 사용자가 입력하는 동안, 유효한 이메일 형식이면 필드 옆에 초록 체크
- 유효하지 않으면 회색 아이콘
- 제출 시도 시 여전히 유효하지 않으면 "올바른 이메일이 아니에요" 표시
```

### 시나리오 3: 메시지에 5자만

- 짧은 메시지는 스팸 확률 높음.
- 최소 10자 검증 추가.

v0에게:
```
메시지 필드 아래에 실시간으로 글자 수를 표시해줘 (예: "8 / 최소 10자").
10자 미만이면 회색, 10자 이상이면 초록.
```

## Step 6. 성공 후 처리 개선

메시지 전송 성공한 뒤 사용자 경험이 매끄러워야 해요.

```
폼 제출이 성공하면:
- 폼 대신 큰 체크 아이콘과 함께 
  "메시지 잘 받았어요! 
   보통 24시간 안에 답장 드립니다. 편하게 기다려주세요."
  라는 카드가 나타나게 해줘.
- 카드 아래에 "새 메시지 보내기" 버튼 (누르면 폼이 다시 나옴).
- 부드러운 페이드 애니메이션.
```

## Step 7. 스팸 방지 - honeypot 필드

봇(자동 프로그램)이 여러분 폼을 스팸으로 폭탄 처리할 수 있어요. 간단한 방지책이 있습니다.

```
폼에 honeypot 필드를 추가해줘.
- name="_gotcha" 인 텍스트 input.
- CSS로 완전히 숨김 (사람 눈엔 안 보임, 하지만 봇은 채움).
- Formspree는 이 필드가 채워져 있으면 자동으로 스팸으로 판단.
```

이거 한 줄이면 스팸의 90%가 걸러집니다.

## Step 8. 로딩 상태 개선

큰 사이트는 로딩 상태가 자연스러워요. 우리도 그렇게:

```
제출 버튼이 "전송 중..."일 때:
- 버튼 왼쪽에 작은 로딩 스피너 아이콘
- 버튼 배경 색깔이 살짝 어둡게
- 폼의 다른 입력들도 disabled

전송 완료 후 다음 폼을 열 때:
- 폼 필드들이 모두 초기화
- 첫 필드(이름)에 자동 포커스
```

## Step 9. 접근성 (Accessibility) 고려

시각장애인분들도 스크린 리더로 폼을 쓸 수 있어야 해요.

```
폼의 접근성을 개선해줘:
- 모든 input에 <label> 태그 명확히 연결 (for/id 매칭)
- placeholder만 있는 label 방식이 아닌, 실제 label을 위에 표시
- 에러 메시지는 aria-describedby로 연결
- 제출 버튼에 aria-label
- 키보드로 Tab 키만 눌러도 순서대로 이동 가능
```

이게 뭔지 몰라도 됩니다. v0가 알아서 처리해요.

## Step 10. Publish

이번 배포 확인:

1. **Publish** 클릭.
2. 배포 완료 후 **실제 배포 URL의 /contact**로 이동.
3. 폼 채우고 제출 → 여러분 이메일에 도착 확인.

**배포 환경에서도 폼이 제대로 작동하는지 반드시 확인**하세요.

## 자주 발생하는 상황

### ❓ 제출 후 새 창으로 Formspree 페이지가 뜸

**원인**: `<form action=...>` 방식(전통 방식)으로 만들어짐.

**해결**:
```
폼을 fetch로 백그라운드 요청 방식으로 바꿔줘. 
페이지 이동 없이 성공/실패 상태만 갱신.
```

### ❓ CORS 에러가 콘솔에 뜸

**원인**: Formspree 요청에 잘못된 헤더.

**해결**:
```
fetch 요청에 다음 헤더를 정확히 추가해줘:
- "Accept": "application/json"
- "Content-Type": "application/json"
```

### ❓ 이메일이 도착 안 함

**원인**: 첫 제출 후 인증 링크를 클릭 안 함.

**해결**: 이메일함(스팸함 포함)에서 Formspree의 인증 링크 이메일 확인 → 클릭.

### ❓ 이메일에 스팸이 너무 많이 옴

**해결**:
1. Step 7의 honeypot 필드 확실히 적용.
2. Formspree 대시보드에서 **reCAPTCHA 활성화**.
3. 심하면 폼에 hCaptcha 위젯 추가 요청.

### ❓ 폼 스타일이 다른 페이지랑 안 어울림

**해결**:
```
폼의 스타일을 사이트 전체 스타일과 통일해줘. 
같은 브랜드 색상, 같은 폰트, 같은 그림자 스타일 사용.
```

## 심화 (선택) - 뉴스레터 신청 폼

문의 폼 말고도 다른 종류의 폼을 만들어보세요. 예: **뉴스레터 구독 폼**.

```
홈 페이지 하단에 뉴스레터 구독 섹션 추가해줘.
- 제목: "새 프로젝트 소식 받기"
- 부제: "이메일 하나만 남겨주시면 새 프로젝트를 올릴 때마다 알려드려요."
- 이메일 입력 필드 하나 + "구독" 버튼 (같은 줄에 나란히)
- 별도의 Formspree endpoint 사용: [여러분 두 번째 폼 endpoint URL]
- 성공 시 "구독해주셔서 감사해요! 곧 첫 소식으로 만날게요."
```

Formspree에서 새 폼을 하나 더 만들면 두 번째 endpoint URL이 나옵니다. 필드가 이메일 하나뿐이라 훨씬 간단.

## 이번 주 과제

1. **/contact 페이지의 폼이 실제로 이메일로 전송되도록** 완성. 배포 URL 제출.
2. **최소 3개의 검증 규칙** 적용 (필수 필드, 이메일 형식, 최소 글자 수).
3. **honeypot 스팸 방지** 적용.
4. 여러분 실제 이메일로 폼 제출 → 도착 확인 → 스크린샷 (Formspree 이메일 & 여러분 이메일).
5. **선택 도전**: 뉴스레터 구독 폼도 추가.
