## 이번 주에 할 일

Week 2·3에서 만든 **PRD + 설계 문서**를 실제 화면으로 옮깁니다. AI Studio Build를 열고, 그 문서들을 프롬프트에 담아 첫 프로토타입을 생성해요.

이번 주는 인터랙션·데이터·AI는 나중이고, **눈에 보이는 화면**만 완성. 아직 폼이 눌러도 아무것도 안 해도 OK.

### 결과물

- 사이트맵의 모든 페이지가 존재하는 프로토타입
- 페이지 간 이동이 되는 네비게이션
- 색깔·폰트가 디자인 토큰에 맞게 적용됨
- 공개 URL로 배포

## Part 1. 개발 사이클 - Build v1

우리 개발은 3주에 걸쳐 3단계로 진행됩니다.

- **v1 (Week 4)** — 눈에 보이는 것 (Visual): 화면·레이아웃·색.
- **v2 (Week 5)** — 움직이는 것 (Interactive): 폼·저장·상태.
- **v3 (Week 6)** — 똑똑한 것 (Intelligent): AI 기능.

각 단계마다 **배포**해서 실제로 확인합니다. "다 만들고 배포"가 아니라 **자주 배포**가 정석.

## Part 2. AI Studio Build로 첫 요청

<a href="https://aistudio.google.com" target="_blank">aistudio.google.com</a> → **Build** (또는 **Apps**) 메뉴 → **+ New project**.

프로젝트 이름을 여러분 PRD에 정한 앱 이름으로.

## 사이트맵
Next.js App Router로 다음 페이지들을 만들어줘.
- / (홈)
- /edit (자소서 입력)
- /result (첨삭 결과)  
- /history (지난 자소서 목록)
- /settings (설정)

## 디자인 토큰

### 색상
- Primary: #2563EB (블루)
- Secondary: #7C3AED (바이올렛)
- Background: #F8FAFC
- Text: #0F172A
- Muted: #64748B

### 폰트
- 본문: Pretendard (한글 최적화)
- 강조: 굵은 산세리프

### 스타일 톤

## 페이지 요구사항

### / (홈)
- 히어로: 큰 인사말 + 앱 한 줄 소개
- CTA: "지금 시작하기" 버튼 (누르면 /edit 이동)
- 아래에 앱 특징 3개 카드
- 페이지 하단에 후기 섹션 (가짜 후기 3개)

### /edit (입력 화면)
- 상단 뒤로가기 버튼
- 회사명 input (필수)
- 직무 input (필수)
- 자소서 textarea (크게, 500자 이상)
- 하단 "첨삭받기" 버튼 (지금은 눌러도 /result로 이동만)
- 폼 검증: 빈 입력 시 알림

### /result (결과 화면)
- 상단: 회사명·직무 요약
- 3개 섹션 (탭 or 아코디언):
  1. 구조 첨삭
  2. 임팩트 첨삭
  3. 회사 적합성
- 각 섹션에 임시 더미 텍스트 (Week 6에서 AI로 실제 채움)
- 하단 "다시 시도" 버튼

### /history (지난 자소서)
- 카드 그리드 (3열, 반응형)
- 각 카드: 회사명·날짜·짧은 미리보기·상태 배지
- 클릭 시 /result로 이동

### /settings (설정)
- 프로필 (이름·이메일)
- 알림 옵션 (토글)

## 공통 요소 (모든 페이지)
- 상단 헤더 (로고 좌측, 메뉴 우측): 홈·입력·지난·설정
- 현재 페이지 메뉴 항목 강조
- 하단 푸터 (심플하게)

## 인터랙션
- 페이지 이동: next/link의 <Link>로 부드럽게 (새로고침 없음)
- 헤더 스크롤 시 상단 고정 (배경 반투명)
- 카드 hover 시 살짝 떠오름 (transform + shadow)

## 반응형
- 데스크톱: 카드 3열
- 태블릿 (768px 이하): 2열
- 모바일 (640px 이하): 1열
- 헤더 메뉴는 모바일에서 햄버거로

## 페이지 밖 세팅
- 반드시 한국어 텍스트
- 접근성: label 태그, alt 속성, 키보드 focus
- SEO: metadata (title, description) 설정

## Part 4. 프로토타입 확인

미리보기가 뜨면 **다음 5가지**를 하나씩 체크하세요.

### 체크 1. 페이지 존재

미리보기 URL에서 사이트맵의 모든 페이지에 접속되는지.

```
/
/edit
/result
/history
/settings
```

각 페이지를 열어봐서 페이지가 뜨는지, 404가 뜨는지 확인.

### 체크 2. 네비게이션 작동

헤더 메뉴 클릭 시 페이지 이동이 되는지. 페이지 새로고침이 아니라 부드럽게 이동해야 함.

### 체크 3. 디자인 토큰

색깔이 프롬프트에 넣은 값들과 일치하는지. 폰트가 지정한 것으로 뜨는지.

### 체크 4. 반응형

미리보기 창을 좁혔다 넓혔다 해보세요. 카드 배치가 반응하는지.

### 체크 5. 모바일 미리보기

미리보기의 폰 아이콘 or "Mobile" 옵션 → 폰 크기에서 확인.

## Part 5. 반복 개선 - 5회 대화

한 번에 완벽하게 안 나옵니다. **같은 대화창에서** 하나씩 요청.

### 반복 1: 큰 문제부터

```
/history 페이지가 완전히 비어있어. 
카드 6개(더미 데이터)로 채워줘. 
각 카드: 회사명·직무·날짜·미리보기 40자.
```

### 반복 2: 인터랙션

```
헤더 메뉴에서 현재 페이지 항목이 강조되도록 
usePathname() 사용해서 스타일 다르게 해줘.
```

### 반복 3: 폼 검증

```
/edit 페이지에서 회사명·직무·자소서 중 하나라도 
비어있으면 [첨삭받기] 버튼 disabled로.
```

### 반복 4: 시각적 개선

```
카드에 hover 시 위로 4px 뜨고 그림자 진해지는 
전환 효과 넣어줘. transition 300ms.
```

### 반복 5: 마무리

```
모바일에서 헤더 메뉴가 화면 넘어가. 
햄버거 아이콘으로 접히게 해줘.
```

## Part 6. 배포 & 확인

미리보기가 만족스러우면 **Publish** 버튼.

- 프로젝트 이름 확인.
- 배포 30초~2분 대기.
- **URL 발급됨** → 복사.

### 3곳에서 확인

1. **시크릿 브라우저**: 로그인 없이도 뜨는가.
2. **다른 브라우저** (Chrome이면 Edge): 호환성.
3. **폰**: 진짜 폰에서 실사용.

## Part 7. 자주 발생하는 상황

### ❓ 페이지가 안 생기고 하나로 다 나옴

**원인**: AI가 라우팅을 이해 못 했음.

**해결**:
```
현재는 모든 내용이 한 페이지에 있어. 
Next.js App Router를 사용해서 
app/edit/page.tsx, app/result/page.tsx 같은 파일로 
각 페이지를 실제로 분리해줘.
```

### ❓ 색깔이 지정한 대로 안 나옴

**해결**: CSS 변수로 색깔을 관리하도록 요청.

```
globals.css에 CSS 변수로 컬러 팔레트를 정의하고
(예: --color-primary: #2563EB), 
모든 색상 사용처에서 그 변수를 참조하도록 리팩터.
```

### ❓ 반응형이 이상하게 됨

**해결**:
```
모바일 (640px 이하), 태블릿 (768px 이하), 데스크톱 별로 
각 페이지가 어떻게 보여야 하는지 다시 검토해서 수정.
카드는 모바일 1열 · 태블릿 2열 · 데스크톱 3열이 원칙.
```

### ❓ 배포는 됐는데 페이지 새로고침 시 404

**원인**: Vercel/Cloud Run 라우팅 세팅 문제.

**해결**: Next.js App Router 프로젝트의 표준 배포를 사용하도록 명시.

```
Vercel 표준 방식으로 배포되도록 next.config를 조정해줘. 
페이지 새로고침 시에도 404 없이 뜨게.
```

### ❓ AI Studio Build가 없거나 안 열림

**대체 경로**: AI Studio에서 **Chat 모드**로 프롬프트 만들고 **"Get code"**로 JavaScript 코드를 받은 뒤 CodePen에 붙여넣기. 다만 이 방식은 여러 페이지가 있는 웹앱을 만들기는 어렵고, 단일 페이지 웹앱만 가능. Week 6에서 이 대체 경로도 상세히 안내합니다.
