## 이번 주에 할 일

Week 4의 프로토타입은 클릭해도 뭐가 저장되지 않죠. 이번 주엔 **실제로 동작하는 웹앱**으로 만듭니다.

- **폼**: 사용자 입력 받기
- **상태 관리**: 화면 간 데이터 공유
- **저장**: 브라우저 껐다 켜도 남아있음 (localStorage)
- **외부 API**: 필요하면 외부 서비스 호출

Week 4 프로젝트를 그대로 이어서, 이번 주 끝나면 **AI 없이도 완전한 웹앱**이 됩니다. AI는 Week 6에서.

## Part 1. 개념 - 상태(State)와 저장(Storage)

### 상태(State)

"지금 이 순간 화면에 뭐가 보이고 있나"의 데이터.

**예시** (자소서 앱):
```
현재 상태:
- 회사명: "카카오"
- 직무: "프로덕트 매니저"
- 자소서 텍스트: "저는 ..."
- 첨삭 결과: (아직 없음)
```

이 상태가 바뀌면 → 화면이 갱신됩니다.

React·Next.js에선 `useState` 훅이 이 역할을 해요. v0나 AI Studio Build가 자동으로 넣어줍니다.

### 저장(Storage)

브라우저의 저장 공간. 종류 3가지.

| 종류 | 특징 | 언제 쓰나 |
|---|---|---|
| **State (메모리)** | 페이지 새로고침하면 사라짐 | 지금 이 순간 데이터 |
| **localStorage** | 껐다 켜도 남아있음. 5MB. 이 기기·이 브라우저만. | 나만 쓰는 앱의 데이터 |
| **서버 DB** | 어디서든 접근. 무한대. 로그인·다기기 동기화 가능. | 여러 사용자가 함께 쓰는 앱 |

강의에선 **localStorage**를 씁니다. 서버 DB는 훨씬 복잡하고 이 강의 범위 밖.

## Part 2. 폼 만들기 - 사용자 입력

Week 4의 `/edit` 페이지에는 이미 폼이 있죠. 지금은 데이터가 어디로 안 가요. **AI Studio Build에 이렇게 요청**하세요 (같은 대화창).

```
/edit 페이지의 폼이 실제로 작동하게 만들어줘.

폼 입력 요소:
- 회사명 (필수, 최소 2자)
- 직무 (필수, 최소 2자)
- 자소서 본문 (필수, 최소 300자, textarea)

폼 제출 시:
1. 각 필드 검증 (빈 값·최소 글자 수)
2. 오류가 있으면 해당 필드 아래에 빨간 텍스트로 안내
3. 검증 통과하면 데이터를 localStorage에 저장
4. 저장된 데이터에 uuid로 id 부여, 저장 시각도 함께
5. /result?id={uuid}로 이동

localStorage 구조:
- key: "essays-v1"
- value: [
    {
      id: string (uuid),
      company: string,
      role: string,
      content: string,
      createdAt: string (ISO)
    },
    ...
  ]

UX:
- 자소서 textarea 아래에 실시간 글자 수 표시 ("245 / 최소 300자")
- 300자 미만이면 회색, 이상이면 초록
- 제출 중일 때 버튼 disabled + 로딩 스피너
```

## Part 3. 상세 페이지 - id로 데이터 불러오기

`/result` 페이지가 URL 파라미터(`?id=xxx`)를 받아 해당 자소서를 표시하도록:

```
/result 페이지가 URL의 id 쿼리 파라미터를 받아 
localStorage에서 해당 자소서를 찾아 표시하도록 해줘.

- id에 해당하는 자소서가 없으면 "찾을 수 없어요" + [홈으로] 버튼
- 있으면 상단에 회사명·직무·작성 시각 표시
- 아래에 자소서 원문 표시 (읽기 전용)
- 첨삭 결과 섹션은 3개 (구조·임팩트·적합성):
  - 각 섹션에 지금은 "Week 6에서 AI가 첨삭할 예정" 안내문
```

## Part 4. 목록 페이지 - localStorage 읽기

`/history` 페이지가 저장된 모든 자소서를 카드 리스트로 표시:

```
/history 페이지가 localStorage의 "essays-v1"에서 
모든 자소서를 읽어 카드 그리드로 표시하도록.

각 카드:
- 회사명 (제목)
- 직무 (부제)
- 작성 시각 ("2일 전" 형식, date-fns 같은 라이브러리)
- 자소서 첫 60자 미리보기 (넘치면 ...)
- 상태 배지: "첨삭 대기" or "첨삭 완료" (지금은 모두 대기)
- 우측 하단 삭제 버튼 (휴지통 아이콘)

정렬:
- 최신순 (createdAt 내림차순)

인터랙션:
- 카드 클릭 시 /result?id=xxx로 이동
- 삭제 버튼 클릭 시 확인 팝업 → localStorage에서 해당 항목 제거 → 리스트 갱신
- 저장된 자소서가 하나도 없으면 "아직 저장된 자소서가 없어요" + [지금 작성하기] 버튼
```

## Part 5. SSR 대응 - Next.js에서 localStorage 다루기

Next.js는 서버에서 먼저 렌더링(SSR)합니다. 서버엔 `window`도 `localStorage`도 없어서 그냥 쓰면 오류.

이건 자주 나는 실수라서 미리 요청:

```
localStorage 사용 시 SSR 대응을 확실히 해줘.

원칙:
1. 초기값은 항상 빈 배열 [] (서버·클라이언트 동일)
2. useEffect 안에서만 localStorage.getItem 접근 (마운트 후)
3. 상태 변경 시 useEffect로 localStorage.setItem 저장

Hydration mismatch 없어야 함.
```

## Part 6. 외부 API 연결 (선택)

프로젝트에 따라 외부 데이터가 필요하면.

### 예시 앱들과 필요한 API

| 프로젝트 | 외부 API |
|---|---|
| 여행 계획 앱 | 날씨 (Open-Meteo, 무료) |
| 뉴스 큐레이터 | RSS 피드, NewsAPI |
| 카페 갤러리 | 카카오맵 API |
| 뮤직 앱 | Spotify API |
| 논문 요약 | Semantic Scholar API |

### 무료 API 몇 가지

- **Open-Meteo** (날씨): 인증 필요 없음. https://open-meteo.com/
- **JSONPlaceholder** (더미 데이터): 개발용 가짜 데이터.
- **REST Countries** (국가 정보): 인증 필요 없음.

### API 호출 요청 예시

여행 앱에 날씨 붙이는 경우:

```
사용자가 목적지를 입력하면 Open-Meteo API로 현재 날씨를 가져와 
카드로 표시하는 기능 추가.

API: https://api.open-meteo.com/v1/forecast?latitude={lat}&longitude={lon}&current_weather=true

- 도시명 → 위경도 변환은 Geocoding API 사용 
  (https://geocoding-api.open-meteo.com/v1/search?name={city})
- 결과: 온도, 풍속, 날씨 코드
- 로딩·에러 상태 UI 처리
- 인증 필요 없음 (무료 API)
```

## Part 7. 이번 주 배포 & 확인

Publish 후 프로덕션 URL에서 다음 시나리오를 실제로 돌려보세요.

### 시나리오 1: 처음 사용

1. 시크릿 브라우저로 접속 (완전 새 사용자 시뮬레이션)
2. 홈에서 "시작하기" → /edit
3. 회사명·직무·자소서 입력 → 제출
4. /result에서 저장된 데이터 확인
5. 헤더 "지난 자소서" 클릭 → 방금 저장한 게 카드로 보임

### 시나리오 2: 재방문

1. 브라우저 완전 닫기
2. 다시 열어서 접속
3. /history에서 이전 자소서가 남아있는가? ← **이번 주 핵심**

### 시나리오 3: 검증 오류

1. /edit에서 아무것도 안 채우고 제출
2. 각 필드에 오류 메시지 표시되는가?
3. 자소서만 100자로 채워도 제출 안 되는가?

세 시나리오 다 통과하면 완성.

## Part 8. 자주 발생하는 상황

### ❓ 새로고침하면 데이터 사라짐

**원인**: localStorage에 저장 안 되고 있음 or SSR mismatch.

**해결**:
```
localStorage 저장이 안 되는 것 같아. 
useEffect로 상태 변경 시 자동 저장하는 로직을 다시 만들어줘. 
그리고 마운트 시 localStorage.getItem 확실히 실행되는지 콘솔로그 넣어줘.
```

### ❓ 여러 탭 열면 데이터가 안 맞음

**원인**: 각 탭이 독립적으로 상태 관리.

**해결**: 
```
storage 이벤트를 리스닝해서 다른 탭에서 localStorage가 바뀌면 
현재 탭 상태도 갱신되게.
```

### ❓ 실수로 삭제한 경우 복구 불가

**해결**:
```
삭제 시 확인 팝업 대신 하단에 "실행 취소" 스낵바를 5초간 표시. 
5초 안에 클릭하면 복구, 지나면 완전 삭제.
```

### ❓ localStorage 5MB 한도 초과

**해결**: 자소서 텍스트가 정말 길면 문제. 각 자소서 100KB 이하 유지. 앱 자체적으로도 최대 50개까지만 저장하는 정책 추가.

```
localStorage 최대 50개 자소서까지만 저장. 
새로 저장할 때 이미 50개면 가장 오래된 것 자동 삭제 
(사용자에게 알림 표시).
```
