## 개념 - 종이에 쓴 것 vs 서랍에 넣은 것

브라우저의 **기억 방식**을 두 가지로 나눠 이해합시다.

**① 종이에 쓴 것 (지금 화면 상태)**
- 지금 이 순간 화면에 보이는 것.
- **새로고침하면 사라짐**.
- 예: 방금 입력한 텍스트, 지금 눌러둔 탭.

**② 서랍에 넣은 것 (브라우저 저장소)**
- **새로고침해도 남아있음**.
- **브라우저 껐다 켜도 남아있음**.
- 예: 카톡 로그인 상태, 인스타 최근 검색어.
- 이걸 기술 용어로 **localStorage**라고 불러요.

Week 4 앱은 지금 ①만 씁니다. 이번 주엔 ②를 붙입니다.

> 참고로 완전히 다른 사람과도 같이 쓰려면 **서버 저장소**(구글 드라이브 같은 것)가 필요한데, 이건 이 강의 범위 밖. 우리는 "**내 컴퓨터에서만 남는**" 수준으로 만듭니다.

## 단계 1. 폼 입력값이 사라지지 않게 하기

Week 4의 자소서 입력 페이지(`/edit`)를 실제로 작동하게 만듭니다.

AI Studio Build에 아래 프롬프트를 복사·붙여넣기:

```
/edit 페이지의 폼이 실제로 작동하도록 바꿔줘.

지금 문제:
- 사용자가 회사명·직무·자소서를 입력해도 아무 데도 저장되지 않음.
- "첨삭받기" 버튼을 눌러도 다음 페이지로 넘어가지 않음.

원하는 동작:

1) 각 입력창에 실시간 검증
- 회사명: 최소 2자
- 직무: 최소 2자
- 자소서: 최소 300자
- 자소서 입력창 아래에 실시간 글자 수 표시:
  "245자 / 최소 300자" (300자 미만이면 회색, 이상이면 초록)

2) 검증 미통과 시
- 해당 입력창 아래 빨간 글씨로 안내:
  "이 항목은 필수예요" 또는 "300자 이상 작성해주세요"

3) 검증 통과 후 "첨삭받기" 클릭 시
- 입력한 내용에 고유 번호(uuid)를 붙여 브라우저 저장소에 저장
- 저장 시각도 함께 기록
- /result?id={번호}로 이동

4) 저장 형식
- 저장 위치: 브라우저의 localStorage
- 저장 이름(key): "essays-v1"
- 저장 형태: 배열로 여러 개를 관리
- 각 항목의 구조:
  {
    id: 고유번호,
    company: 회사명,
    role: 직무,
    content: 자소서 본문,
    createdAt: 저장 시각 (ISO 형식)
  }

5) 사용자 경험
- 제출 중일 때: 버튼 텍스트를 "저장 중..."으로 바꾸고 disabled
- 저장 성공 후 자동으로 다음 페이지로 이동
- 이동 후에는 폼 초기화

주의: 새로고침해도 저장된 내용이 사라지지 않아야 함.
```

**Run** → 1~2분 대기.

### 확인하기

미리보기에서 실제로 돌려보세요.

1. `/edit` 접속.
2. 회사명 한 글자만 입력 → **오류 메시지가 뜨는가?**
3. 자소서에 100자만 입력 → **글자 수 카운터가 회색인가?**
4. 300자 이상 채우고 → **글자 수 카운터가 초록으로 바뀌는가?**
5. 정상 입력 후 제출 → **다음 페이지로 이동하는가?**

## 단계 2. 저장된 내용 다시 불러오기

`/result` 페이지가 URL의 번호로 저장된 자소서를 찾아 보여주도록 합니다.

```
/result 페이지가 URL의 id를 읽어서 
방금 저장한 자소서를 화면에 표시하도록 해줘.

동작:
1. /result?id=xxx로 접속하면 
   브라우저 저장소("essays-v1")에서 그 id의 자소서를 찾음.
2. 찾으면 상단에 회사명·직무·작성 시각 표시.
   그 아래에 자소서 원문을 읽기 전용으로 표시.
3. 못 찾으면 "찾을 수 없어요" 메시지 + "홈으로" 버튼.

첨삭 결과 섹션 (지금은 자리만 잡기):
- 구조·임팩트·회사 적합성 3개 섹션
- 각 섹션에 "AI 첨삭은 Week 6에서 붙일 예정" 안내 텍스트.
- 이 자리 placeholder는 회색 박스로 표시.

작성 시각은 "2일 전", "방금 전" 같은 상대 시간으로 표시.
```

### 확인하기

1. `/edit`에서 자소서 저장.
2. 자동으로 `/result?id=xxx`로 이동.
3. 방금 입력한 회사명·직무·본문이 그대로 뜨는가?
4. **F5 (새로고침)** 눌러보기 → **여전히 남아있는가?** ← 이게 핵심.
5. 브라우저를 아예 닫았다가 다시 열어 같은 URL 접속 → **여전히 있는가?**

이 5가지가 다 되면 저장 시스템이 잘 작동하는 것.

## 단계 3. 저장한 것들 목록 보기

`/history` 페이지에서 저장된 모든 자소서를 카드로 보여줍니다.

```
/history 페이지를 지난 자소서 목록으로 만들어줘.

동작:
1. 브라우저 저장소에서 모든 자소서를 불러옴.
2. 카드 그리드로 표시 (데스크톱 3열, 모바일 1열).
3. 최신 작성순으로 정렬.

각 카드 구성:
- 상단 큰 글씨: 회사명
- 그 아래 회색: 직무
- 오른쪽 위 상태 배지: 
  "첨삭 대기" (회색) 또는 "첨삭 완료" (파란색)
  (지금은 모두 "첨삭 대기"로)
- 자소서 첫 60자 미리보기 (넘치면 ... 처리)
- 하단: 작성 시각 (상대 시간) · 삭제 버튼 (🗑️)

인터랙션:
- 카드 클릭 → /result?id={그카드의id}로 이동
- 삭제 버튼 클릭 → 확인 팝업 
  ("이 자소서를 삭제할까요? 되돌릴 수 없어요.")
  → 확인하면 저장소에서 제거하고 화면에서도 사라짐

빈 상태:
- 저장된 자소서가 0개면 카드 대신
  "아직 저장된 자소서가 없어요"
  큰 이모지 📝
  "지금 첫 자소서 작성하기" 버튼 (누르면 /edit)
```

### 확인하기

1. 자소서 2~3개 더 저장 (다른 회사·직무로).
2. `/history` 접속 → 카드 여러 개가 뜨는가?
3. 최신순 정렬이 맞는가?
4. 카드 하나 클릭 → 해당 자소서 상세 페이지로 이동되는가?
5. 삭제 버튼 → 확인 팝업 뜬 뒤 진짜로 사라지는가?

## 단계 4. 헤더에 개수 표시 (작은 디테일)

작지만 앱을 프로답게 보이게 만드는 요소.

```
헤더의 "지난 자소서" 메뉴 옆에 저장된 개수 배지를 추가해줘.

- 저장된 자소서가 0개면 배지 안 보임.
- 1개 이상이면 파란 원 안에 숫자 표시. 예: 지난 자소서 (3)
- 값이 실시간으로 반영 (저장하면 +1, 삭제하면 -1).
```

## 단계 5. 흔한 문제와 해결

여기까지 하다 보면 자주 나오는 문제들과 대처법.

### 새로고침하면 저장한 게 사라짐

원인: **저장은 됐는데 불러오기가 안 됨**.

이렇게 요청하세요:

```
새로고침하면 저장한 자소서 목록이 초기 상태로 돌아가버려.
페이지가 처음 뜰 때 브라우저 저장소에서 데이터를 
꺼내오는 로직이 확실히 실행되도록 다시 만들어줘.

특히 Next.js 서버 렌더링과 클라이언트 렌더링이 
어긋나는 문제(hydration mismatch)를 피하도록 처리.
```

### 여러 탭을 열면 데이터가 안 맞음

원인: 각 탭이 독립적으로 화면을 그림. 한 탭에서 저장한 걸 다른 탭이 모름.

```
여러 탭을 켠 상태에서 한 탭에서 저장/삭제하면 
다른 탭의 화면도 자동으로 갱신되게 해줘.
```

### 실수로 삭제한 걸 되돌리고 싶음

```
삭제 후 화면 하단에 5초간 "실행 취소" 스낵바를 표시해줘.
5초 안에 클릭하면 삭제 취소.
5초 지나면 완전히 사라짐.
```

### 오래된 자소서가 너무 많아짐

브라우저 저장소는 **5MB 한도**가 있어요. 자소서를 100개 저장하면 슬슬 문제.

```
저장된 자소서가 50개 넘으면 새로 저장할 때 
가장 오래된 것 하나를 자동으로 삭제해줘. 
사용자에게 알림도 표시:
"저장 공간이 부족해 [회사명] 자소서를 자동 삭제했어요."
```

## 단계 6. (선택) 외부 데이터 가져오기

프로젝트에 따라 인터넷에서 정보를 가져와야 할 때가 있어요.

예를 들면:
- **여행 앱** → 목적지의 날씨
- **뉴스 앱** → 최신 헤드라인
- **환율 앱** → 지금 환율

이런 걸 **외부 API 호출**이라고 부르는데, 어려운 말 다 빼면 그냥 **"다른 회사 서버에 정보 물어보기"** 예요.

### 예시: 여행 앱에 날씨 붙이기

여행 앱을 만들고 있다면 이렇게 요청:

```
/plan 페이지에서 사용자가 목적지 도시명을 입력하면 
현재 날씨를 카드로 표시해줘.

기술 세부사항:
- Open-Meteo라는 무료 API 사용 (회원가입 불필요)
- 도시명 → 위경도 변환:
  https://geocoding-api.open-meteo.com/v1/search?name={도시}
- 위경도 → 날씨:
  https://api.open-meteo.com/v1/forecast?latitude={위도}&longitude={경도}&current_weather=true

날씨 카드 표시 내용:
- 도시명
- 큰 온도 (섭씨)
- 날씨 아이콘 (맑음·구름·비 등)
- 풍속

로딩 중일 때는 "날씨 확인 중..." 스피너.
실패하면 "날씨를 가져올 수 없어요" 메시지.
```

무료 API 몇 가지 (회원가입 없이 바로 씀):

- <a href="https://open-meteo.com/" target="_blank">**Open-Meteo**</a> — 날씨
- <a href="https://restcountries.com/" target="_blank">**REST Countries**</a> — 국가 정보 (인구·언어·통화)
- <a href="https://jsonplaceholder.typicode.com/" target="_blank">**JSONPlaceholder**</a> — 개발용 가짜 데이터 (테스트에 유용)

### 어떻게 알아냈나?

**API 무료 여부·사용법을 AI Studio Chat에 직접 물어보세요.**

```
[내 프로젝트: 여행 앱]

이 앱에 실시간 날씨 기능을 넣고 싶어. 
무료로 쓸 수 있는 API 중 
회원가입이 필요 없고 사용법이 쉬운 것 3개만 추천해줘.

각각에 대해:
- API 이름과 사이트 URL
- 회원가입 필요 여부
- 요청 예시 (curl 명령어)
- 응답 예시
- 하루 사용 한도
```

## 단계 7. 배포하고 확인하기

수정된 앱을 배포해서 진짜로 잘 되는지 확인.

Publish 버튼 → 배포 완료 → 배포된 URL로 접속.

### 3가지 시나리오 실행

**시나리오 A: 처음 방문**
- 시크릿 브라우저로 접속 (완전히 새 사용자 흉내).
- 홈 → /edit → 자소서 입력 → 저장.
- /history 접속 → 방금 저장한 게 카드로 보이는가?

**시나리오 B: 재방문**
- 브라우저 완전히 닫기.
- 다시 열어서 배포 URL 접속.
- /history 접속 → **이전 자소서가 여전히 있는가?** ← 이번 주 최고의 순간.

**시나리오 C: 삭제 & 실수 방지**
- /history에서 카드 하나 삭제.
- 확인 팝업 뜨는가?
- 삭제 후 화면에서 사라지는가?
- (선택 구현했다면) "실행 취소" 5초 안에 클릭하면 복구되는가?

## 이번 주 과제

1. **저장 기능 완성** & 배포. 배포 URL 제출.
2. **시나리오 A·B·C 3가지 통과** 확인 스크린샷.
3. **개발 다이어리** 최소 3개 세션 기록.
4. **선택 도전**: 외부 API 1개 연결 (프로젝트 성격에 맞게).
