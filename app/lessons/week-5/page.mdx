## 이번 주에 할 일

카페 리스트, 여행지 앨범, 맛집 카탈로그, 서점 도서 목록… 이런 앱은 뭐가 공통일까요?

**같은 형태의 카드가 여러 개 반복**되고, 사용자가 **검색·필터·정렬**할 수 있다는 점.

이번 주엔 이런 앱의 뼈대를 완성합니다. 여러분의 취향을 반영해 만들어보세요:
- 여행지 갤러리 (가본 곳 or 가고 싶은 곳)
- 카페 리스트 (핫한 카페 모음)
- 책 추천 목록
- 좋아하는 영화 아카이브
- 학교 동아리 소개

**한 번 배우면 다 응용 가능한 패턴**이에요.

## 5분 개념 - 데이터와 반복 렌더링

지금까지는 화면의 텍스트·이미지를 **하나하나 직접 배치**했죠. 이번엔 다릅니다.

### 데이터 = 정보의 리스트

```
카페들 = [
  { 이름: "블루보틀 성수", 지역: "성수동", 평점: 4.5, 이미지: "..." },
  { 이름: "센터커피", 지역: "합정", 평점: 4.3, 이미지: "..." },
  { 이름: "프릳츠", 지역: "홍대", 평점: 4.7, 이미지: "..." },
  ...
]
```

이런 형태를 **배열(array)**이라고 해요. 각 항목은 **객체(object)**.

### 반복 렌더링

카드 하나만 만들어놓고 "이 배열의 각 항목마다 이 카드를 그려줘"라고 하면 → 항목 수만큼 카드가 자동 생성됩니다.

**장점**: 
- 데이터만 늘리면 화면도 자동으로 늘어남
- 데이터를 정렬하면 화면도 자동 정렬
- 검색어로 데이터 필터링하면 화면도 자동 갱신

**이번 주 핵심**: v0에게 "이 형태의 데이터가 있다, 이 데이터로 카드 그리드를 만들어줘" 하고 부탁하는 요령.

## Step 2. 첫 요청 - 카페 갤러리 앱

이번 강의에서는 **서울 카페 도장깨기 갤러리 앱**을 예로 만듭니다. 여러분은 좋아하는 주제로 바꿔도 됩니다.

```
서울의 예쁜 카페들을 소개하는 갤러리 웹앱을 만들어줘.
Next.js App Router로.

기능:
1. 상단에 검색창 (카페 이름으로 검색)
2. 검색창 아래에 지역 필터 버튼들 
   (전체 / 성수 / 합정 / 홍대 / 이태원 / 압구정)
3. 필터 옆에 정렬 드롭다운 (인기순 / 평점순 / 최신순)
4. 하단에 카페 카드 그리드 (반응형: 데스크톱 3열 → 태블릿 2열 → 모바일 1열)

카페 카드 구성:
- 상단: 이미지 (16:9 비율)
- 이미지 위에 지역 태그 (좌상단), 하트 아이콘 (우상단)
- 이미지 아래: 카페 이름 (굵게), 지역 (회색), 별점 (★★★★☆ 형태 + 숫자)
- 짧은 설명 2줄 (넘치면 ...)
- "자세히 보기" 링크

카페 데이터 (배열로 10개 하드코딩):
1. 블루보틀 성수 (성수, 4.5) - "미니멀한 공간에서 맛보는 스페셜티 커피"
2. 센터커피 합정점 (합정, 4.3) - "합정의 아지트, 매일 다른 원두"
3. 프릳츠 홍대 (홍대, 4.7) - "빵과 커피의 완벽한 조화"
4. 앤트러사이트 한남 (이태원, 4.6) - "숨은 명소, 조용한 공간"
5. 리사르 커피 (성수, 4.4) - "성수의 명물, 시그니처 라떼"
6. 폰트 (합정, 4.2) - "심플한 공간의 심플한 커피"
7. 스몰카페 (홍대, 4.5) - "홍대 골목의 작은 보물"
8. 커피에일리언스 (이태원, 4.3) - "블랙 톤의 감각적인 공간"
9. 카페 로터스 (압구정, 4.4) - "정갈한 티 셀렉션"
10. 프로토콜 (성수, 4.6) - "인더스트리얼 감성"

이미지는 https://picsum.photos/400/300?random=1 부터 ?random=10까지 사용.

인터랙션:
- 검색: 검색어를 입력하면 실시간으로 카드 필터링 (카페 이름에서 부분 매치)
- 필터: 지역 버튼 클릭 시 해당 지역만 표시
- 정렬: 드롭다운 선택 시 즉시 카드 순서 재정렬
- 하트 아이콘: 클릭 시 채워지고 색이 빨갛게 (일단 UI만)
- 카드 hover 시 살짝 떠오르는 그림자 효과

디자인:
- 파스텔·모던 톤 (연한 크림 배경, 브라운 포인트)
- 폰트: Pretendard
- 각 카드는 라운드 코너 (2xl)
- 부드러운 그림자
- 넉넉한 여백

모바일:
- 검색창 상단 고정
- 필터 버튼은 가로 스크롤 가능하게
- 카드 1열
```

**Enter** → 2~3분 대기.

## Step 3. 검색·필터·정렬 테스트

미리보기에서:

1. **검색창에 "성수" 입력** → 성수동 카페만 남아야.
2. **"합정" 버튼 클릭** → 합정 카페만.
3. **정렬 "평점순" 선택** → 별점 높은 순으로 재정렬.
4. **필터 + 검색 조합**: 지역 "성수" + 검색어 "블루보틀" → 블루보틀 성수만 표시.

이런 조합이 자연스럽게 작동해야 완성입니다.

### 잘 안 되면

```
검색과 필터가 동시에 작동하지 않아. 
검색어와 필터가 모두 적용된 상태로 카드가 표시되도록 해줘.
```

## Step 4. 카드 hover 효과 세밀하게

```
카드 hover 시 다음 효과들이 부드럽게 동시에 발생하게 해줘:
- 살짝 위로 4px 이동
- 그림자가 더 진하고 넓게
- 이미지가 살짝 확대 (scale 1.05)
- "자세히 보기" 링크 아래 밑줄이 나타남

transition 시간은 300ms로 부드럽게.
```

## Step 5. 하트 (좋아요) 기능 - localStorage 없이

지금은 하트를 클릭해도 페이지 새로고침하면 사라지죠. 상태만 있는 UI:

```
하트 아이콘 클릭 상태를 각 카드마다 관리해줘.
- 클릭하면 빨간색으로 채워지고, 다시 클릭하면 회색으로.
- 카드 위에 "❤️ 좋아요 수" 표시 (초기값 각 카드마다 5~50 랜덤).
- 하트 클릭 시 좋아요 수가 +1 or -1.

지금은 새로고침하면 초기화되어도 OK. Week 6에서 
localStorage로 저장하는 법을 배울 거예요.
```

## Step 6. 검색어 하이라이트

멋진 디테일:

```
검색 결과에서 검색어와 일치하는 부분을 
카드의 카페 이름 안에서 노란 배경으로 하이라이트해줘.

예: 검색어 "블루" → "블루보틀 성수"에서 
"블루" 부분이 노란 배경.
```

## Step 7. 결과 없음 상태

검색 결과가 하나도 없을 때는?

```
필터/검색 결과가 0개일 때 표시할 화면을 만들어줘:
- 큰 커피컵 이모지 ☕
- "이 조건에 맞는 카페가 없어요" 메시지
- "필터 초기화" 버튼 (누르면 모든 필터 해제)

카드 그리드가 있어야 할 자리에 이 화면이 대신 표시.
```

## Step 8. 카드 상세 페이지 (라우팅 응용)

지난주 Week 3의 라우팅을 응용. 카드 클릭 → 상세 페이지.

```
각 카페 카드를 클릭하면 상세 페이지로 이동하게 해줘.
- URL 형식: /cafes/[slug]
- 예: 블루보틀 성수 → /cafes/blue-bottle-seongsu

상세 페이지 내용:
- 상단에 큰 이미지 (가로 전체 폭)
- 이미지 아래: 카페 이름, 지역, 별점, 좋아요 수
- 상세 설명 (하드코딩된 200자 정도)
- 정보 카드들: 영업시간, 대표 메뉴, 가격대, 좌석 수
- "리스트로 돌아가기" 버튼 (뒤로가기)
- 하단에 "이 카페 근처의 다른 카페" 3개 카드

동적 라우팅: app/cafes/[slug]/page.tsx 로 만들되, 
각 slug에 대응하는 데이터는 배열에서 찾아 표시. 
없는 slug면 not-found로.
```

**참고**: 상세 페이지의 데이터도 하드코딩 배열에서 온다면, 카드 리스트와 상세 페이지가 같은 데이터를 공유해야 해요:

```
카페 데이터를 app/data/cafes.ts 파일로 분리해서 
카드 목록과 상세 페이지가 모두 참조하도록 해줘.
```

클릭하면 데이터에서 랜덤 카페 하나를 골라 상세 페이지로 이동.

## Step 11. 코드 살펴보기 (선택)

"Code" 탭에서 데이터 배열 파일 확인:

```typescript
// app/data/cafes.ts
export const cafes = [
  {
    slug: "blue-bottle-seongsu",
    name: "블루보틀 성수",
    region: "성수",
    rating: 4.5,
    description: "미니멀한 공간에서 맛보는 스페셜티 커피",
    image: "https://picsum.photos/400/300?random=1",
    likes: 42,
    hours: "07:00 - 22:00",
    signature: "블랙 아메리카노",
    priceRange: "6,000 - 8,000원"
  },
  ...
]
```

이렇게 데이터가 배열로 있고, 페이지들이 이 배열을 참조합니다.

앞으로 카페를 하나 더 추가하려면:
- 이 파일에 객체 하나만 더 넣으면 → 자동으로 목록에 나타나고 상세 페이지도 생김.
- **데이터만 늘리면 화면도 자동으로 늘어난다** — 이게 이 패턴의 힘입니다.

## Step 12. 여러분 주제로 확장

카페 대신 여러분 취향을 반영해봅시다.

```
카페 데이터를 여러분이 좋아하는 것으로 바꿔줘. 예:
- 봉준호 감독의 영화 아카이브
- 좋아하는 K-드라마 목록
- 가고 싶은 여행지 리스트
- 추천 도서 리스트

배열 구조는 그대로 두되, 이름·설명·이미지·태그 등을 
그 주제에 맞게 대체해줘.

지역 필터를 "장르 필터" or "카테고리 필터"로 바꾸고,
별점 대신 다른 지표(예: 개봉연도, 계절, 출간연도)를 
표시해도 좋아.
```

## 자주 발생하는 상황

### ❓ 필터 여러 개가 동시에 안 됨

**해결**:
```
검색 + 지역 필터 + 정렬이 모두 동시에 적용된 상태로 
카드가 표시되도록 로직을 다시 짜줘. 
useState로 각각 관리하고 useMemo로 결과 배열을 계산.
```

### ❓ 이미지 로딩이 오래 걸림

**원인**: picsum.photos는 실제 이미지를 랜덤 서비스에서 가져와서 느릴 수 있음.

**해결**: 
```
picsum.photos 대신 실제 이미지 URL 배열로 바꿔줘. 
[여러분이 unsplash 등에서 찾은 카페 이미지 URL 10개]
```

Unsplash에서 무료 이미지 찾는 법: <a href="https://unsplash.com/s/photos/cafe" target="_blank">unsplash.com/s/photos/cafe</a> → 원하는 이미지 우클릭 → "이미지 주소 복사".

### ❓ 상세 페이지에서 새로고침하면 404

**원인**: Next.js는 정적 생성 시 slug 목록이 필요함.

**해결**:
```
동적 라우트에 generateStaticParams를 추가해서 
빌드 시 모든 슬러그를 미리 생성하도록 해줘.
```

### ❓ 모바일에서 필터 버튼이 화면 밖으로 나감

**해결**:
```
모바일 화면에서 필터 버튼들을 가로 스크롤 가능한 
scrollable row로 만들어줘. 
overflow-x: auto, whitespace-nowrap 활용.
```

## 이번 주 과제

1. **카페 갤러리(또는 여러분 취향 주제)** 앱 완성 & 배포. URL 제출.
2. 10개 이상의 데이터 항목.
3. **검색·필터·정렬 모두 작동**.
4. 카드 상세 페이지 라우팅.
5. **선택 도전**: 상세 페이지에 지도(Google Maps iframe)나 이미지 캐러셀 추가.
