## 이번 주에 할 일

마지막 주. **프로덕션 배포**와 **공식 런칭**입니다.

Week 1~7 동안 여러분은:
- Week 1: 첫 배포 감 잡기
- Week 2: PRD 작성
- Week 3: 화면 설계
- Week 4~6: 개발 (Visual → Interactive → Intelligent)
- Week 7: QA

지금 여러분 앱은 이미 인터넷에 있어요. 이번 주는 그걸 **프로덕트답게 마무리**하고, **세상에 공식 소개**합니다.

### 결과물

- 프로덕션 배포 (안정된 URL)
- 커스텀 도메인 연결 (선택)
- OG 미리보기·파비콘·SEO 태그
- Google Analytics
- 회고문 (500자)
- 런칭 발표 (SNS or 커뮤니티)

## Part 1. 프로덕션 배포 - 어디에?

여러분 앱을 어디에 배포할지 결정. 옵션 3가지.

### 옵션 A: AI Studio Build의 기본 배포

Week 4부터 써온 배포. **가장 간단**.
- 장점: 원클릭 배포, 코드 관리 필요 없음.
- 단점: URL이 AI Studio 도메인에 종속. 커스텀 도메인 제한 있을 수 있음.

### 옵션 B: Vercel

Next.js·React 앱의 표준 배포 플랫폼. **가장 강력**.
- 장점: 커스텀 도메인 무료, 자동 재배포, Analytics 내장, 좋은 성능.
- 단점: GitHub 저장소가 있어야 함.
- URL 예: `myapp.vercel.app`

### 옵션 C: Cloud Run (Google Cloud)

Google 서비스. AI Studio와 자연스럽게 연동.
- 장점: 확장 좋음, GCP 다른 서비스와 통합.
- 단점: 초보엔 세팅 복잡, 요금 관리 필요.

**추천**: AI Studio Build 기본 배포로 시작 → 커스텀 도메인이 필요하면 Vercel로 옮기기.

## Part 2. Vercel로 옮기기 (커스텀 도메인 원하는 경우)

이건 선택. 필수 아님.

### Step 1. 코드 export

AI Studio Build 화면에서 **⋯ 메뉴 → "Export code"** 또는 **"Download as ZIP"**.

ZIP을 로컬 폴더에 압축 해제.

### Step 2. GitHub에 올리기

<a href="https://github.com/new" target="_blank">github.com/new</a>에서 새 저장소 만들기.

- Repository name: `my-app-name`
- Public 선택.
- Create repository.

로컬에서 (터미널이 필요합니다):

```bash
cd my-app-name
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/여러분/my-app-name.git
git push -u origin main
```

터미널이 낯설면 <a href="https://desktop.github.com/" target="_blank">**GitHub Desktop**</a> 앱 설치 → GUI로 같은 작업 가능.

### Step 3. Vercel Import

<a href="https://vercel.com/new" target="_blank">vercel.com/new</a> → GitHub 계정 연결 → 방금 만든 저장소 Import.

Framework: **Next.js** 자동 감지 → **Deploy**.

Vercel Dashboard → 프로젝트 → **Settings → Environment Variables** → Week 6의 `GEMINI_API_KEY` 추가.

## Part 3. 커스텀 도메인 (선택)

기본 `myapp.vercel.app` 대신 `myapp.com` 같은 개인 도메인.

### 도메인 구매

- <a href="https://vercel.com/domains" target="_blank">**Vercel Domains**</a> — Vercel과 자동 연결. 편함. `.com` 연 US$12 수준.
- **가비아** (한국) — 한글 지원. `.com` 연 15,000원.
- **Cloudflare Registrar** — 원가 가까움 (US$9~10). DNS 관리도 편함.
- **Namecheap** — 저렴한 편.

### 이름 정하기 팁

- 짧고 기억하기 쉽게
- 여러분 앱 목적 반영 (예: `essaycritic.com`, `paperslim.com`)
- 다른 브랜드와 겹치지 않게
- 흔한 실수 없이 (하이픈·숫자·오타 유도되는 글자 피하기)

### Vercel에 연결

- Vercel Dashboard → 프로젝트 → **Settings → Domains** → **Add**.
- 여러분 도메인 입력 (예: `myapp.com`).
- Vercel이 안내하는 DNS 레코드를 도메인 판매처의 DNS 관리에 입력:
  - **A 레코드**: `76.76.21.21`
  - 또는 **CNAME**: `cname.vercel-dns.com`
- 15분 ~ 몇 시간 안에 자동 연결.

### HTTPS

Vercel은 **Let's Encrypt** 인증서를 자동 발급·갱신. 여러분이 할 일 없음. `https://` 즉시 지원.

## Part 4. SEO & 메타 태그

검색 엔진(구글·네이버)이 여러분 앱을 잘 찾을 수 있게.

```
루트 레이아웃에 다음 메타데이터를 세팅해줘. Next.js Metadata API 사용.

- title: "자소서 첨삭 도우미 - 15년차 인사담당자 AI 첨삭"
- description: "취업 준비생을 위한 AI 자소서 첨삭 도구. 3가지 관점으로 
  구조·임팩트·회사 적합성을 검토해드립니다. 무료 시작."
- keywords: ["자소서 첨삭", "AI 첨삭", "취업 준비", "자기소개서"]
- author: "김지은"
- locale: "ko_KR"
- openGraph:
  - title: (동일)
  - description: (동일)
  - type: "website"
  - url: "https://myapp.com"
  - siteName: "자소서 첨삭 도우미"
  - images: [{ url: "/og-image.png", width: 1200, height: 630 }]
- twitter:
  - card: "summary_large_image"
  - title: (동일)
  - description: (동일)
  - images: ["/og-image.png"]
```

## Part 5. OG 이미지 - SNS 공유 미리보기

카톡·트위터·페이스북에 URL 공유 시 뜨는 미리보기 이미지.

### 방법 1: 동적 OG 이미지 (Next.js)

```
app/opengraph-image.tsx 파일 만들어줘.
- ImageResponse로 동적 생성
- 크기: 1200x630
- 배경: 앱 브랜드 그라데이션
- 중앙에 큰 앱 이름 + 부제
- 우측 하단에 앱 URL
```

### 방법 2: 정적 이미지

<a href="https://www.canva.com" target="_blank">Canva</a>에서 1200×630 이미지 만들어 `public/og-image.png`에 저장.

### 확인

<a href="https://socialsharepreview.com/" target="_blank">socialsharepreview.com</a>에 여러분 URL 넣으면 각 SNS에서 어떻게 보이는지 미리 확인.

## Part 6. 파비콘 (탭 아이콘)

브라우저 탭에 뜨는 작은 아이콘.

### 이모지 파비콘 (초간단)

`app/icon.tsx`:

```
32x32 크기의 이모지 기반 파비콘을 만들어줘. 
Next.js의 icon 규칙 사용.
이모지: 🎯 (앱 상징)
배경: 그라데이션 (프라이머리 색)
```

### 이미지 파비콘

로고 이미지를 <a href="https://favicon.io/favicon-converter/" target="_blank">favicon.io</a>에 업로드 → 자동으로 여러 크기 생성 → 다운로드 → `public/` 폴더에 저장.

## Part 7. Google Analytics - 방문자 통계

누가·언제·어디서 접속하는지 아는 것.

### 세팅

1. <a href="https://analytics.google.com" target="_blank">analytics.google.com</a> → 새 속성 만들기.
2. 스트림 유형: **Web**.
3. Measurement ID (`G-XXXXXXXXXX`) 발급.
4. AI Studio Build에 요청:

```
Google Analytics 4를 설치해줘. 
Measurement ID: G-XXXXXXXXXX

- app/layout.tsx에 gtag 스크립트 추가
- 페이지 뷰 자동 추적
- 다음 이벤트 커스텀 추적:
  - 자소서 제출 (essay_submit)
  - 첨삭 완료 (critique_complete)
  - 재첨삭 요청 (critique_retry)
```

### Vercel Analytics (더 간단)

Vercel Dashboard → 프로젝트 → **Analytics** 탭 → **Enable**. Google Analytics보다 간단하지만 데이터가 얕음.

## Part 8. 런칭 발표 🚀

만들었으면 알려야죠.

### 발표 준비물

- **앱 URL** (커스텀 도메인 or Vercel)
- **스크린샷** 3장 (홈·핵심 기능·결과)
- **간단한 데모 영상** (30초~1분, Loom or QuickTime)
- **소개글** 200자

### 소개글 템플릿

```
🚀 [앱 이름] 런칭했어요!

[문제 정의 한 문장]
저는 [경험/불편]을 겪었는데, 
그래서 만들어봤어요. [주요 기능 1~2개].

[페르소나]에게 필요한 도구가 됐으면 해요.

👉 링크: https://myapp.com

피드백 환영합니다!
```

### 발표할 곳

- 📱 **인스타그램 스토리** (여러분 팔로워)
- 💬 **오픈채팅** (관심사 커뮤니티)
- 🐦 **X(Twitter)** (`#내가만든AI앱` 해시태그)
- 💼 **LinkedIn** (취업 준비생이면 필수)
- 🎬 **유튜브** (짧은 데모 영상)
- 📧 **부모님·교수님께 직접 링크**

각 채널의 반응이 다르니 여러 곳에 발표하세요.

## Part 9. 회고문 - 이 강의를 마치며

500자 이내로 다음을 정리.

```md
# 이 강의를 마치며

## 1. 어떤 문제를 해결하고 싶었나?
[Week 2 PRD로 돌아가 보고 처음의 문제와 지금의 결과 비교]

## 2. 8주간 무엇을 배웠나?
### 기술적으로
[SDLC·프로토타이핑·QA·배포 등 배운 개념들]

### 사고방식·태도
[개발자·프로덕트 메이커의 사고방식으로 배운 것]

## 3. 뭐가 가장 어려웠나?
[가장 힘들었던 순간, 어떻게 넘겼나]

## 4. 뭐가 가장 재미있었나?
[가장 뿌듯한 순간, 자랑스러운 부분]

## 5. 다음에 더 배우고 싶은 것?
[HTML/CSS 기초? 파이썬? 특정 도메인?]
```

이 회고문을 앱의 About 페이지에 실어도 좋아요. 프로젝트에 이야기가 생깁니다.

## Part 10. 발표 (수업에서 발표한다면)

3~5분 발표 구성.

3. **기술 하이라이트** (1분): 어떤 주차 기술을 어떻게 조합했나?
4. **어려웠던 점** (30초): 뭘 배웠나?
5. **다음 단계** (30초): 이 프로젝트를 더 발전시킨다면?

## 축하합니다 🎉

여러분은 오늘 **프로덕트 메이커**로 졸업합니다.

- 아이디어를 문서화하고 (기획)
